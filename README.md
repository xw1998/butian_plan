# 补天计划（Butian Plan）

当前发布：**0.1.1rc2 通用 MCP 接入与审计修复版**。支持宿主 AI 通过标准输入输出 MCP 调用，不依赖 Ollama 或本地模型。验证范围与剩余限制见 [补充发布记录](docs/发布补充验证-20261013.md)。

补天计划是一个与具体 AI 对话工具解耦的多 Agent 协作运行时。

它的核心工作方式不是让多个成员在群聊里模拟开会，而是由一个派活者与用户直接对话，负责理解需求、拆解任务、分发工作、组织审核并交付结果；不同岗位的子 Agent 扮演具体组员，独立完成研究、实现、测试、审查和复盘。

```text
用户
  ↕
派活者 / 主 Agent
  ├─ 研究子 Agent
  ├─ 实现子 Agent
  ├─ 测试子 Agent
  └─ 审核子 Agent
```

## 核心能力

- 单人模式：用户直接与一个数字人协作，适合简单任务。
- 团队模式：派活者负责对接用户，子 Agent 按岗位分工执行任务。
- 数字人资产：支持配置名称、人格、职级、岗位、职责、模型和工具权限。
- 独立记忆：每个数字人拥有隔离的长期记忆、经验和教训，并支持热、温、冷、归档生命周期。
- 任务闭环：支持拆解、分发、执行、审核、返工、阻塞和取消。
- 通用 Agent Provider：通过能力协商接口接入不同 Agent 运行时、模型 API、本地模型、MCP 或人工执行，不为任何单一产品定制核心生命周期。
- 内置成员：以独立空白记忆初始化六名数字人，不导入女娲计划历史资产；历史迁移入口明确拒绝执行。

## 单人模式与团队模式

单人模式适合目标清晰、无需交叉验证的任务。选定一个数字人后，该数字人直接理解和执行任务，并使用自己的独立记忆。

团队模式适合复杂任务。派活者是用户的主要对话人，子 Agent 只以自己的身份执行分配到的任务。派活者必须汇总可复核证据，不能把尚未验证的子 Agent 输出直接当成最终事实。

两种模式都必须在界面和 API 中明确显示。模式切换不能删除历史任务或记忆；运行中的任务也不能被静默取消。

详细需求、任务状态机、记忆字段、上下文连续性和实现验收标准见 [`docs/需求计划.md`](docs/需求计划.md)。

## 防止上下文黑洞

补天计划不把 AI 对话窗口当作唯一事实来源。当前任务状态、用户纠正、未决问题、证据、任务交接和下一步动作都会写入结构化状态包与追加事件日志。

长会话接近上下文窗口时，系统按“当前指令、当前任务、近期事件、相关记忆、历史索引”分层压缩。低优先级历史可以裁剪，但当前用户约束、任务状态、最近纠正、未决问题和下一步动作不能丢失。压缩快照保留父快照、事件范围和校验信息，重启后可以恢复或从事件日志重建。

子 Agent 交给派活者的是带任务版本、状态、证据、环境、未完成事项和下一步动作的结构化交接包，不是无法追溯的一段文本。已证伪、环境不匹配和低置信推测不会无提示地进入确定性上下文。

## 经验与教训：可积累的资产

补天计划中的经验和教训不是普通聊天记录，而是可以持续改善 Agent 的重要工程资产。

它们可以用来：

- 调整数字人的提示词和工作方法。
- 选择更合适的模型、工具和子 Agent。
- 改进任务拆解、审核和验证策略。
- 在相同环境下复用已经验证过的解决方案。
- 识别已知失败条件，避免重复踩坑。

使用工具或外部软件时，经验和教训必须绑定环境信息，包括软件名称、版本号或 commit、模型版本、操作系统、依赖版本、关键配置、复现步骤、证据路径、验证时间、适用范围和失效条件。版本无法确认时必须标记为 `unknown`，不能把不同版本下的行为自动合并。

经验和教训会从实践结果中自动吸收，不把人工确认作为学习前置条件。做事成功就记录方法和环境作为经验；做事失败就记录失败方法和环境作为教训；相同方法再次成功或失败时，使用 `log1p` 饱和曲线更新权重，重复次数越多，新增一次结果的收益越低。客户提出异议时，异议会自动记录为待评估的反证事件。系统需要核对版本、输入、配置、复现结果和替代解释后，才能判定证伪成立；证据不足时只能标记争议或临时降权，不能直接推翻原经验。没有充分证据的内容仍必须标注低置信度或未验证状态。

## 做梦机制：让 Agent 从实践中发现新线索

做梦是独立记忆系统的后台维护机制，主要由经验和教训积累到足够数量与强度时触发，而不是单纯按固定时间触发。它从已经记录的经历、经验和教训中寻找：

- 新的记忆关联。
- 尚未解决的知识缺口。
- 互相矛盾的经验。
- 可以在未来任务中验证的候选假设。

做梦产物默认属于推测内容，不能直接当作事实。只有经过真实实践、人工确认或可靠证据验证后，才可以转化为高可信经验或教训。

做梦优先从权重最高、证据最充分、最近验证过的记忆事件开始；越久远、越少验证或已证伪的事件，进入梦境的概率越低。原有闸门继续保留：积累足够的经验和教训、满足最短间隔、新增片段达到阈值、取得做梦锁，并受操作数和成本上限限制。只有同时满足条件才运行。这样既能让模型及时拓展想象，也能避免无意义地反复调用模型。

经验、教训和做梦机制共同构成补天计划的长期资产。记忆还会经历热、温、冷和归档生命周期：长期不用的经验会进入冷数据，后续任务命中时以“需要重新验证”的历史参考方式复温；同一经验在新实践中还会形成 v1、v2、v3 的修订链，把更好的步骤、工具、前置条件和验证方式逐步合并进去，重新成功后才逐步恢复权重。这就是“温故而知新”：经验会在实践中变得更好，而不是简单恢复旧权重。内置成员从独立空白记忆开始，经验、教训和工具验证数据只通过本系统实际运行逐步积累。所有 Agent 工具均通过通用 Provider 能力协议接入，不包含固定产品的插件界面、会话生命周期或特殊功能。它们可以帮助调整 AI，使 Agent 在可追溯、可验证的前提下逐步改进，而不是把“自进化”实现成不可解释的自动改写。

## 技术路线

第一阶段推荐使用 **Python 3.11+**：

- 标准库已经覆盖 SQLite、异步任务、命令行、HTTP 和数据处理的基础需求。
- `sqlite3`、`asyncio`、`pathlib`、`json` 等可以减少外部依赖。
- 适合先把记忆、任务状态机和 Provider 抽象跑通。
- OpenAI 兼容接口、Ollama、MCP 和本地脚本都有成熟接入方式。

初期目标是尽量少安装环境：Python 3.11+、SQLite 和项目自身代码即可启动最小闭环。后续只有在接口稳定、确有需要时再引入轻量 Web 框架或其他依赖。Python 不是零环境方案，但可以通过 Windows 启动脚本、版本检查和自动创建虚拟环境降低配置成本。

核心接口保持平台无关；外部 Agent 工具只实现通用 Provider 能力协议，能力不支持时明确返回 `unsupported` 或 `unknown`。

## 快速开始

### 环境要求

- Python 3.11+（仅使用标准库，无第三方依赖）
- SQLite（Python 内置）

### 安装与运行

```bash
# 1) 初始化运行时（默认目录 ~/.butian，可用 BUTIAN_HOME 指定）
python -m butian.cli init

# 2) 添加一个数字人成员
python -m butian.cli member add m1 Alice

# 内置六名数字人由初始化流程创建，各自使用独立空白记忆。
# 历史迁移不在当前范围内，migrate 入口返回明确拒绝。

# 3) 启动团队工作台（本地 HTTP API + Web 控制台）
python -m butian.cli serve --host 127.0.0.1 --port 8765
#   浏览器打开 http://127.0.0.1:8765

# 4) 以 MCP 服务方式接入（JSON-RPC over stdin/stdout）
python -m butian.cli mcp
```

### 接入 AI 应用

宿主应用支持 stdio MCP 时，配置命令 `python`、参数 `["-m", "butian.cli", "mcp"]`，工作目录设为仓库目录，环境变量 `BUTIAN_HOME` 指向你的数据目录。Python 应使用已安装本项目的解释器。不同客户端配置字段不同，详细流程见 [通用 AI 应用接入](docs/通用AI应用接入.md)。

宿主 AI 自己负责理解目标和生成结果，调用补天的任务、上下文、证据、审核与记忆工具；这条路径无需 providers.json、模型 API Key 或 Ollama。补天主动启动独立子 Agent 时，才配置可选 Provider。没有 MCP/API/进程接口的应用只能人工交接。

### 控制台视图

总览、任务、验证、记忆、进化、成员六个工作区。「成员」视图展示成员身份与配置；历史资产导入不在当前范围内。其中「进化」是数字人自由进化的操作台：技能阶段、记忆合成、记忆维护（退化评估/降温/复温/版本链）、梦境自省（运行/蒸馏/抽象/提出假设/安排验证/记录结果）、验证批次、以及假设与验证队列。

### 常用 CLI

```bash
python -m butian.cli evolution skills m1
python -m butian.cli evolution dream-run m1 --min-fragments 1
python -m butian.cli evolution history m1
```

## 项目状态

当前仓库包含 SQLite 运行时、HTTP API、MCP 工具、CLI 命令组、Web 控制台，以及记忆合成、技能演化、退化维护、版本链和假设验证等模块。历史迁移保持拒绝执行。

模块存在和测试通过不代表全部产品需求已验收。真实模型理解、完整浏览器业务链、跨平台接入和自主进化需要各自的运行证据；本地回显 Provider 只能验证执行传输与状态链。测试见 `tests/`，验收要求见 [`docs/需求计划.md`](docs/需求计划.md)。

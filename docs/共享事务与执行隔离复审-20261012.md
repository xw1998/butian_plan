## 已复现并修复

1. 跨会话父子任务：Store.create_task 原允许第二个 session 的任务挂入第一个 session 的父任务。新增 parent_session_mismatch 校验；拒绝后任务数量不变。
2. 领取任务绕过共享事务锁：主线程持 Store._write_lock 时，另一线程仍完成 claim_task。领取现使用 serialized_write，与其他任务事务使用同一 RLock。
3. 旧 Provider 会话继续执行：新会话建立后，显式消费旧会话仍启动真实 Python 子进程。消费入口现拒绝 provider_execution_superseded；会话持久化 task_revision，运行任务的 revision 不匹配时拒绝；返回结果写回前再检查当前会话和 revision。此检查不等于完全解决所有并发执行交错。
4. 在他人会话创建任务：MCP 调用者可通过 assignee_id 指向自己向外部会话插入任务。MCP 与 HTTP 现要求调用者是会话 dispatcher。Store 内部创建仍供受信任服务流程使用。
5. 假设账本绕过共享事务锁：持 Store 锁时 add_prior 仍写入同一连接。HypothesisStore 现接收 Store 的共享 RLock；包含复合观察事务的数据库方法均同步。独立构造时使用本地 RLock。

身份认证与 Provider 会话读取也补充 Store 共享锁，减少 HTTP POST/MCP 在其他事务中穿插访问的入口。没有把整个长工具请求锁住，以免阻止主动取消。

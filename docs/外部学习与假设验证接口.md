# 外部学习与假设验证接口

本接口将外部来源主张作为先验候选，而不是事实。来源登记记录 locator、内容 SHA-256、标题、抓取时间和元数据；主张记录适用条件、限制和来源置信度。将主张转换为先验后，仍需单独提出假设、定义验证动作并获得明确授权。

## HTTP

- `POST /api/knowledge/capture`：显式抓取公开 HTTP(S) URL，字段 `url`，可选 `title`、`source_type`、`timeout`、`max_bytes`。服务会拒绝 localhost、私网、回环、链路本地、多播、保留地址和带凭据 URL；重定向逐跳复核，响应体有大小上限。成功后自动登记来源、计算 SHA-256 并立即校验，返回 `run_id`、`source_id` 和最终定位。失败仍写入运行台账。
- `GET /api/knowledge/runs`：查看学习运行台账。

- `POST /api/knowledge/sources`：字段 `source_type`、`locator`、`title`、`content_hash`，可选 `metadata`。
- `POST /api/knowledge/claims`：字段 `source_id`、`claim`，可选 `conditions`、`limitations`、`confidence`。
- `POST /api/hypotheses/from-claim`：字段 `claim_id`，生成 `candidate` 先验。
- `POST /api/hypotheses/observe`：字段 `action_id`、`outcome`、`independent_key`，可选 `evidence_ids`、`actor_member_id`、`member_id`、`environment`、`notes`。支持或拒绝结论必须绑定团队证据台账中仍有效且当前调用者可访问的文件。提供 `member_id` 时，支持观察只生成低权重、低置信度的候选记忆，不直接升级为可信经验或教训。

## MCP

对应工具为 `butian_knowledge_source_add`、`butian_knowledge_claim_add`、`butian_hypothesis_from_claim` 和 `butian_hypothesis_observe`。证据访问使用 `actor_member_id` 并遵守团队证据 ACL。

## 约束与未覆盖项

- `content_hash` 由登记方提供；当前实现登记来源定位和哈希，不负责网页/论文抓取，也不验证该哈希确实来自 locator 指向的内容。
- 来源主张到先验的转换不会自动推导完整实践假设；验证假设、预测、反证条件和验证动作仍由调用方显式构造。
- 一次支持观察只生成 candidate 记忆。经验/教训的多次独立复现门槛、冲突处理和版本生命周期尚需后续统一接入。
- HTTP/MCP 是本机服务入口，不替代部署层身份认证；向非可信网络暴露前必须补齐统一认证和传输保护。

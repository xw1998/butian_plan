# 实现状态与产品验收矩阵

初始日期：2026-10-11；复核更新：2026-10-14。此矩阵保留能力与证据范围，不作为全需求完成声明。

## 结论

当前工具执行后端是 `python_host` / `host_process`。它提供临时工作目录、超时、输出上限和进程树终止尝试，但不是操作系统级安全沙箱。以下 OS 强制隔离能力当前明确为未提供：文件系统隔离、网络隔离、子进程隔离、内存限制、文件大小限制、进程树强制控制。主动取消已有生产入口，但是否确认停止必须以真实进程清理结果和审计为准；不能把请求取消写成已停止。用户已重新授权真实停止验收；九项复验实际7失败、2通过。最小探针的进程树观测成功，停止调用实际抛PermissionError且未提供错误码；退出未确认时保持unknown，当前环境中的真实停止能力未通过验收。host_trusted 是经显式授权的同账户宿主运行，不是沙箱。

因此，产品文案、API 返回和验收报告不得把应用层权限、路径校验或临时目录描述成 OS 强制隔离；涉及高风险工具时必须 fail-closed，要求可用的隔离后端，或拒绝执行。

## Fail-closed 规则

1. manifest 声明任何当前后端不具备的隔离能力时，执行必须返回 `tool_isolation_backend_unavailable`，不能降级执行。
2. 未绑定真实 execution、verification 或 evidence 的统计、配对和熔断恢复不得自动通过。
3. dispatcher 未配置时，超时升级必须报错并保留原 issue，不猜测负责人。
4. 未经成员鉴权的 HTTP/MCP 工单查询、接单、完成和拒绝必须拒绝。
5. 模拟 Provider、浅层单测和静态代码检查只能作为局部证据，报告中必须单独标注，不能写成真实闭环通过。

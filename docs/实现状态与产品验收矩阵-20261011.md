# 实现状态与产品验收矩阵

日期：2026-10-11

## 结论

当前工具执行后端是 `python_host` / `host_process`。它提供临时工作目录、超时、输出上限和进程树终止尝试，但不是操作系统级安全沙箱。以下能力当前明确为未提供：文件系统隔离、网络隔离、子进程隔离、内存限制、文件大小限制、进程树强制控制、主动取消。

因此，产品文案、API 返回和验收报告不得把应用层权限、路径校验或临时目录描述成 OS 强制隔离；涉及高风险工具时必须 fail-closed，要求可用的隔离后端，或拒绝执行。

## Fail-closed 规则

1. manifest 声明任何当前后端不具备的隔离能力时，执行必须返回 `tool_isolation_backend_unavailable`，不能降级执行。
2. 未绑定真实 execution、verification 或 evidence 的统计、配对和熔断恢复不得自动通过。
3. dispatcher 未配置时，超时升级必须报错并保留原 issue，不猜测负责人。
4. 未经成员鉴权的 HTTP/MCP 工单查询、接单、完成和拒绝必须拒绝。
5. 模拟 Provider、浅层单测和静态代码检查只能作为局部证据，报告中必须单独标注，不能写成真实闭环通过。

## 交付声明模板

报告应分别列出：代码已验证、静态确认、真实 Provider/UI 尚未验证、并发/隔离环境尚未验证。测试通过数量只说明测试集合结果，不代表完整产品验收。

## 一、实际复现的问题

### C01 学习资产没有成员归属边界（P0，阻断闭环验收）

步骤：owner 认证创建 source；other 持自己的有效 token，携带 source_id 调用 `/api/knowledge/sources/verify` 和 `/api/knowledge/claims`。
实际：verify HTTP 200，将来源改为 hash_mismatch，且返回 expected_hash；添加主张 HTTP 201。owner 抓取被禁本机 URL 后，other GET `/api/knowledge/runs` 得到 owner-private-marker locator 及失败详情，HTTP 200。

这不是匿名绕过，而是“身份认证成功、资源授权缺失”。若希望来源为团队共享，也必须有明确共享和写入权限；当前不能把知道 ID 当作授权。

根因位置：butian/runtime/learning.py 的 knowledge_sources/source_claims/learning_runs/learning_queue 均无 owner；http_api.py 第294–305行直接调用无 actor 参数的方法；runs 路由直接列全局台账。

修复步骤：
1. 增加 owner_member_id 和必要的 scope/share 关联；claim 从 source 继承归属，run/queue 在创建时绑定 actor，不能从任意 body owner 信任派生。
2. 既有无 owner 数据保持隔离/待认领，不自动归给当前成员；先备份，迁移幂等、有版本和回滚方案。这是补天自身 schema 升级，不导入女娲历史记忆。
3. service/store 层统一 source/claim/run/queue 资源授权，HTTP、MCP、CLI 均调用；列表按授权过滤，变更先授权再执行。
4. URL 去重改为 owner+规范化URL，明确授权共享时才跨成员复用。
5. verify 应记录每次观测而非任何调用都直接覆盖公共可信状态；错误内容不得破坏已有成功验证证据。

先失败回归：双成员 HTTP 与 MCP；B verify/add/prior/read 拒绝且数据库、事件无副作用；A 正常工作；显式共享只读、允许写、撤销后各自行为正确；未知ID不泄露归属信息。

### C02 主张列表写入后不可见（P1）

实际：数据库已产生 claim，GET `/api/knowledge/claims` 仍 HTTP200、claims=[]。源码明确因无归属而固定空列表；hypotheses 路由也有同样静态模式。

保持防泄露边界是正确的临时措施，但空成功结果会把“无法安全查询”伪装成“没有数据”，主张观察与成长入口未闭环。

修复：依赖 C01；实现授权分页查询；暂不可用时返回明确的功能不可用状态，不以空列表表示成功。hypotheses 同步补 ownership 与查询。回归必须创建真实数据再从生产接口读回，并验证其他成员不可见。

### C03 授权列表缺参时无 HTTP 响应（P1）

实际：合法 header 身份 GET `/api/tools/host-authorizations`，没有 member_id query，urllib 得到 RemoteDisconnected：Remote end closed connection without response。
根因：http_api.py 约96–101行 `if not member_id ...: return` 未 `_send`。同类 `/api/tools` 缺参逻辑应一并扫描，但本轮只实际复现授权列表。

修复：有有效 actor 时由 actor 派生 owner；或者缺字段返回结构化400。显式他人 member_id 保持403；所有分支只能发送一次响应。不要把修复改成默认展示全局授权。
回归：匿名401、合法缺参有确定200/400、本人列表、他人403、非法status400、GET/POST一致、响应有JSON和长度。

### C04 学习队列遗留 running 项永久不处理且剩余数失真（P1）

故障注入：enqueue 后把该行置 running，调用 process_learning_queue。
实际：processed=[]、remaining=0、status=completed，但唯一任务仍 running。
根因：learning.py 只选择 pending/failed，remaining 只计 pending；无租约/心跳/过期恢复。

修复：queue 增 claim_token、lease_until、attempts、next_attempt_at、worker；原子竞争领取，只有持有效租约才能完成；启动/维护恢复过期running；失败有限重试与退避、终态失败；状态分别统计pending/running/retryable_failed/dead_letter，不用completed掩盖未完成工作。
回归：本故障注入先红后绿；再真实启动worker→领取→杀worker→重启→回收；两个worker并发仅一个领取；旧worker迟到不能覆盖新结果；抓取副作用/落库有幂等键。

## 二、静态确认的缺口与待验证风险

### C05 外部学习与自由进化主链仍未完成（P1产品阻断）

learning.py process_learning_queue 明确“never creates claims or memories”，返回 claims_created=0、memories_created=0。抓取和哈希台账已具备，但不能满足需求9.2–9.5、23.3的来源→主张→适用性→假设→授权实践→结果→经验→后续使用主链。

修复：抓取后建立可审计候选提取任务，主张绑定快照位置/版本和模型回报；适用性与反例字段强制结构化；生成假设及验证计划；调用现有权限/风险闸门执行真实实践；失败、反证、未知都保留；仅有独立证据时晋升经验。维护调度器只安排有授权且预算内的步骤，不自动审批。后续任务必须记录召回、实际采用和效果反馈。

验收案例：新来源提出候选→授权实践成功→经验候选→独立复验→后续任务采用；另跑反证修订、权限拒绝、来源失效、重启续跑。用真实任务证据串联，不手工改数据库伪造每个状态。

### C06 宿主停止和授权审计仍不充分（P1，风险未实际复现）

tools.py _terminate_process_tree 是 best-effort taskkill，忽略返回码，取消仅以根 proc.poll 判断 cancelled；没有 Windows Job Object 的进程集合存活证明。runtime_capabilities.active_cancellation=False 与已有取消入口不一致，需区分“支持取消请求”和“保证树停止”。host_capabilities 未声明时默认空，授权覆盖检查只能校验声明，不能限制同账户代码真实行为；执行元数据未绑定具体 authorization_id/完整能力集合。

这不是已经证明的“子进程逃逸”漏洞；本轮未运行后代进程存活探针。host_trusted 是同账户授信执行，不能包装成隔离，也不能依赖成员API隔离阻止该代码直接读宿主数据库。

修复：Windows Job Object 管理运行集合，创建/加入需在用户代码开始前完成；停止后核验集合清空，失败返回unknown/cleanup_failed而非cancelled；处理父先退出/后代持stdout/超时/撤销竞态。授权记录绑定工具、版本、源码和manifest哈希、能力/路径/操作/有效期；启动前原子校验，撤销与启动串行化；实际OS管理员权限仍由系统授权。审计保存授权ID和执行环境。平台不支持时声明能力不足，不能伪造成功。

### C07 宿主治理产品入口未接通（P1）

当前 MCP 工具注册/dispatch与 web/app.js 未找到新host授权、运行列表、取消能力映射；目前有HTTP接口，不等于用户可操作完整链。属于静态入口缺口，本轮没有浏览器验证整页行为。

修复：将治理能力接入实际产品配置/审计入口及必要MCP工具；UI真实展示同账户权限、授权范围、撤销状态和运行记录；停止使用既有宿主控制语义，不擅自增加与需求冲突的普通团队停止按钮。按钮结果必须绑定真实授权/运行ID，失败可见。
验收：浏览器中授权→真实执行→列出运行→停止→核验结束→撤销→再执行拒绝；其他成员不可操作；MCP用实际dispatch测试而非只验schema。

### C08 工具分享生命周期测试被 return 截断（P1测试证据缺口）

tests/test_tools.py:242，test_shared_tool_accept_trial_archive_restore 在验证draft不可分享后直接return。accept/trial/archive/restore断言不可达。不能据此断言这些功能有bug，但测试名和通过数不证明生命周期已验收。

修复：拆成draft拒绝与真实active生命周期两个用例；通过真实执行证据激活，不直接SQL置active；全链断言成员归属、share句柄、版本哈希、归档拒绝调用和恢复后重新验证。验证断言确实可失败，避免另一个早退。

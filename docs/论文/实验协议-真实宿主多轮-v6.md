# 实验协议：经验库 vs 纯读源（host-loop-v6）

本文件在任何一次模型调用之前冻结。判据、臂、语料规模、预算档位、判词映射均不得在见到读数后修改；如需修改，另开 v6.1 并说明前一版为何作废。

## 1. 要回答的问题

前五档只回答了「哪个字段承重」：把召回的 `version`/`status` 抹掉，正确率从 12/12 掉到 3/12。它证明的是**元件必要**，不是**整体有效**——把汽车刹车拆掉会出事，不能推出这辆车比别的车好。

本档回答另一个问题：**用了这套工具，比不用它更好吗？**

对照组必须是真正的「不用」：同一批题目、同一个模型、**没有任何经验库**、每题老老实实翻源文档。这一臂在前五档里从未存在过，因此「整体有效性」至今是空白而不是负结果。

## 2. 为什么单一正确率回答不了这个问题

如果翻源文档免费且不限量，「不用经验库」这一臂总能读到正确版本，正确率必然接近满分，任何记忆层都不可能在正确率上超过它。因此只比正确率，本实验注定判不出差异，且结论会被误读成「工具没用」。

真正的价值命题是两条，必须分开测：

- **成本轴**：都不限预算时，同样准的前提下少翻多少手册、少烧多少 token。
- **预算轴**：给两臂**同样有限**的翻手册次数，比谁更准。超预算必须答 `unknown`，不得猜。

预算轴才是检验版本闸门的地方：经验库必须自己判断哪道题值得花掉稀缺的翻手册额度。如果它把额度浪费在记忆本来就有效的题上，它会输。

## 3. 语料

一个 120 实体的契约手册，三族混合（calibration/schema/tool 各 40）：

- 每实体 1–4 个版本，共约 360 条 `RULE` 行，序列化后约 30–40 KB。
- 其中 24 个是**任务实体**（每族 8），另外 96 个是**诱饵实体**：永远不被提问，但真实存在于手册与经验库里。
- 诱饵的作用是让两臂都必须做「定位」：经验库要在召回结果里按实体名过滤，纯读源臂要在几十 KB 里找到那一条。任何一臂拿不到「直接告诉你答案在第 3 行」这种便宜。

经验库预置**全部 120 个实体**的 v1 规则，状态 `warm`，每条两条独立成功证据。所以经验库自己也不知道哪些实体会被提问。

## 4. 轮次与漂移

3 轮。任务实体按固定下标分三档（`index % 3`），漂移日程写死：

| 轮 | 真值版本 | 记忆里的版本 | 陈旧题数 |
|---|---|---|---|
| R1 | 全部 v1 | v1 | 0 / 24 |
| R2 | 下标 ≡0 (mod 3) 的 8 个 → v2 | 仍 v1 | 8 / 24 |
| R3 | 上述 8 个仍 v2；下标 ≡1 (mod 3) 的 4 个首次 → v2 | 仍 v1 | 12 / 24 |

漂移必须真的改变答案：新版本参数与 v1 相同就重抽，直到不同。否则「沿用旧版本」与「正确」答案相同，陈旧检测空转。

## 5. 两臂

| 臂 | 可用工具 | 每题的流程 |
|---|---|---|
| `lib` | `butian_memory_recall`、`butian_knowledge_source_read` | 召回 → 按版本/状态准入 → 一致则直接答；不一致或非 warm 则读源后答 |
| `noref` | 仅 `butian_knowledge_source_read` | 每题读源全文 → 自己定位该实体本轮版本那条 RULE → 作答 |

两臂的系统提示词只在「你用不用经验库」这一点不同；三族换算公式、作答 JSON 格式、精确匹配判分规则逐字相同。

**每题独立上下文，不跨题缓存。** 这是本档唯一一处会影响结论的设计选择，理由与代价在 §8 写明。

## 6. 判据

预算轴取 R3（12 陈旧 / 24 题），两档：`L = 6` 与 `L = 12` 次读源额度。超额后必须 `decision="unknown"`。

- **Z1 正确率不劣（成本轴）**：`acc(lib) >= acc(noref) - 0.05`。
- **Z2 读源显著更少（成本轴）**：`reads(lib) <= 0.5 * reads(noref)`。
- **Z3 基线不残废（反假绿，成本轴）**：`acc(noref) >= 0.95`。基线都答不对说明题目本身不可答或手册有歧义，本档作废重设计，不得以「经验库更好」结案。
- **Z4 预算轴优势**：存在某一档 `L`，使得 `acc(lib@L) - acc(noref@L) >= 0.15`。
- **Z5 不写回**：实验结束后 120 条记忆的内容版本与状态与初始逐条一致（本档不登记实践、不写回，只测「用不用」）。

## 7. 判词映射

| 条件 | 判词 |
|---|---|
| Z1∧Z2∧Z3∧Z4 | `v6_library_effective_both_axes` |
| Z1∧Z2∧Z3∧¬Z4 | `v6_library_effective_cost_only` |
| ¬Z1 | `v6_accuracy_regression`（经验库更差，如实报） |
| ¬Z3 | `v6_baseline_handicapped`（作废，重设计） |

两个宿主分别出判词，再合成总判词：`v6_cross_model_replicated`（两宿主同判词）/ `v6_split`（不同）/ `v6_on_pro_only`（仅 deepseek-v4-pro 成立）。

宿主与分工同 v5：`deepseek-v4-pro` 与会话宿主不同族，承担跨模型结论；`deepseek-flash` 与会话宿主同族，只作独立进程复现。

## 8. 预注册的公平性与边界

**一、每题独立上下文。** 若允许跨题缓存，一个模型只要把 30 KB 手册读进上下文保持打开，就能答对全部题目且只读一次——任何记忆层都输。真实的 agent 服务大量互不相关的请求，正是每题独立上下文。**代价**：这使纯读源臂每题的输入 token 恒等于手册大小，读源成本被高估。若换成常驻上下文，成本轴的差距会缩小，但不会消失（手册会漂移、会超出上下文、会在远端）。

**二、经验库的召回不是提示**。`butian_memory_recall` 是子串模糊匹配，不保证首条就是目标实体，`lib` 必须自己按实体名过滤；召回条数计入其 prompt token。若召回质量差导致 `lib` 输，那是真实发现，不得事后调 `limit`。

**三、算术仍由模型自己做**，主口径用模型选中的规则在本地复算（与 v5 一致），副口径直接判模型答案，两者分列。

**四、不外推**：两个外部模型同属一家厂商；任务族是契约化合成任务，确定性求解器压低了模型噪声也限定了外部有效性；三族换算公式不变、只有参数随版本变，这是简化；漂移日程是协议内设定，不代表真实世界分布。单次 `temperature=0`、无重复采样，不报 p 值。

**五、不测召回写回**：本档不回答「经验库能不能自己学会新版本」，只回答「已经存了正确经验时，用它比不用更好吗」。

## 9. 复现

```
DEEPSEEK_API_KEY=<key> python docs/论文/run_host_v6_effectiveness_study.py \
  --out <绝对目录> --stage {bootstrap,run,report}
```

已结算的臂自动跳过，可断点续跑。每臂的原始调用（messages / reply / usage / served_model）逐条落盘到 `calls/<arm>/<tag>.json`，不含密钥。密钥只从环境变量读取。

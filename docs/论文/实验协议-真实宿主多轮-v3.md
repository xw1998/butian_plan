# 真实宿主多轮实验协议 v3（修复后才做得出来的三问）

- 协议号：`host-loop-v3`
- 预注册时间：2026-11-02（在跑第一次 bootstrap 之前冻结）
- 宿主：当前对话里的真实模型，经 `python -m butian.cli mcp`（stdio）调用补天工具
- 判分：精确匹配，真值由 `run_multiround_study.solve()` 给出
- 产物目录：`docs/论文/experiment_results/host-loop-v3-20261102/`

## 0. 为什么要做这一轮

v2 结果文档第 9 节列了 5 个没回答的问题，其中三条**在修复前根本做不出来**——不是没跑，是跑不出可读的数：

| v2 §9 | 修复前的障碍 | 本轮怎么读 |
| --- | --- | --- |
| 第 1 条：内容正确却被判 `disputed`（误伤）时宿主会不会过度读源、复用收益归零 | v2 只测了"坏内容"这一侧，没有"内容对但被误伤"的构造 | `false-disputed` 组 |
| 第 2 条：修好一条坏记忆的正确路径 | 修前只有状态级降级，没有内容级通道，写坏的记忆永远修不好（`butian_memory_revise` 是 2026-11-02 才有的） | `repair` 组 |
| 第 5 条：几百条记忆时宿主是否顶得住 | 修前召回按二字组命中，一次查询把整库端回，规模一上来读数全是噪声 | `scale` 组 |

三条都是"产品行为问题"，不是模型能力问题，所以只能在同样的真实宿主 + 真实 MCP 链路上测。

## 1. 设计

三个组 × 三个族（`calibration` / `schema` / `tool`）= 9 个实体，每个实体跑 4 轮，共 **36 次作答**。
全部实体 4 轮都是同一个文档版本（`v1`）——本轮不测版本判定（v1、v2 已经测过），只测记忆状态与规模。

| 组 | 实体 | 记忆初始化（bootstrap） | 想问什么 |
| --- | --- | --- | --- |
| `false-disputed` | `{family}101` | 内容**正确**，两条独立成功观察 → `warm`，再补一条失败观察 → `disputed` | 误伤之后宿主会不会答错？复用收益还剩多少？能不能自愈？ |
| `repair` | `{family}201` | 内容是**错值**（一个数值偏 7 或 37），两条独立成功观察 → `warm` | 第 1 轮误用被判错之后，`revise` 能不能把它救回来、几轮回到复用 |
| `scale` | `{family}301` | 正常 `v1` 记忆（内容正确、两条独立成功 → `warm`）+ 库内另有 **300 条同族无关记忆**（每族 100 条，名字 `{family}5xx`） | 库里几百条记忆时召回还准不准、宿主还顶不顶得住 |

300 条无关记忆只影响召回与上下文规模，不设任务，不参与判分。

### 1.1 正式数据前的一处修正（2026-11-02，bootstrap 后、R1 之前）

第一次 bootstrap 把 `scale` 组做成"没有记忆"，于是 R1 召回对三个 `{family}301` 都退回或链兜底，各返回 100 条同族无关记忆。
这不是缺陷，而是召回一直有的有意行为（查询里的实体素未谋面时宁可多给一条，也不装作没经验；见 v2 结果第 11.1 节边界 1），
但它让"规模"这一问被"无记忆兜底"盖住。故按本表把 `scale` 组改成有一条 `warm` 的正常记忆，再跑正式数据；
试点产物保留在 `experiment_results/host-loop-v3-20261102-pilot1/`，不计入任何结论。

## 2. 宿主策略（预注册，判据的可解释性依赖它）

宿主只能做三件事：`butian_memory_recall`、`butian_knowledge_source_read`、提交答案。写回一律由 harness 在客观判分之后执行。
宿主对每道题的决策规则，跑之前就写死，不临时改：

- 召回里存在 **`warm` 或 `hot`** 且 `entity` 与 `version` 都本轮一致的记忆 → 用经验作答，不读源；
- 记忆是 **`candidate` / `disputed`**、或没有本轮版本的记忆 → 读源作答；
- 两者都不成立 → 回答 `unknown`（不得猜）。

于是三个组的预期轨迹是可以事先写下来的，判据也就能判"预期是否成立"，而不是判"我事后觉得好不好"：

- `false-disputed`：4 轮都读源（误伤把 `warm` 打掉，复用收益归零），答案全对；
- `repair`：R1 用坏经验答错 → 修订 → R2/R3 是 `candidate` 所以读源 → 两次独立成功后再回 `warm` → R4 复用；
- `scale`：4 轮都复用（记忆本来就 `warm`），量的是 300 条无关记忆会不会挤进召回。

## 3. 判据（冻结，任一不成立即整体不成立）

| 编号 | 判据 | 成立条件 |
| --- | --- | --- |
| M1 | 误伤不产生错误答案，但复用收益归零 | `false-disputed` 4 轮 **全对**；4 轮 **都读源**（`need_source=True`）；没有任何一轮以 `disputed` 记忆作依据；R4 该记忆状态仍是 `disputed`（自愈失败） |
| M2 | 内容级修订能把坏记忆救回可复用 | R1 至少一次"用经验"且被判 `wrong`（证明坏经验被真的用上）；R2–R4 **全对**；R4 `need_source=False` 且 `basis='experience'`；修订发生在 R1 settle 之后 |
| M3 | 规模不影响召回精度与作答 | 12 次召回（3 实体 × 4 轮）里"与本实体无关的记忆条数"合计 **0**；单次召回条数中位 **≤ 5**；`scale` 组 4 轮全对且 4 轮全部 `need_source=False` |
| M4 | 行为可审计（沿用 v2 的 N5 口径） | 每题都有召回记录与对应工具调用；`basis='experience'` 的答案必须带 `from_memory`，且该 `memory_id` 出现在**该轮**召回结果里；`disputed` 记忆不得作为唯一依据 |

判词（全部成立 / 有任一不成立）：

- 全部成立 → `v3_false_dispute_and_repair_confirmed`
- M1 不成立（误伤组答错或把 `disputed` 当依据） → `false_dispute_produces_wrong_answers`
- M2 不成立且 R4 仍读源 → `revision_insufficient_to_restore_reuse`
- M3 不成立 → `scale_degrades_recall_or_answers`
- M4 不成立 → `behaviour_not_auditable`

## 4. 限制（读结论前必须看）

1. 宿主同时是实验设计者，非盲；本轮尤其重——宿主知道三组的构造。
2. 单宿主、单次运行；不外推到其他模型，不报告 p 值。
3. 坏经验、误伤、300 条无关记忆都是 harness 直接注入的构造，不是真实历史事故。
4. 任务是契约化合成任务，真值由 `solve()` 给出，不涉及真实工程口径。
5. 不测量 token 成本与延迟，不声称模型参数发生变化。
6. `repair` 组的"两次独立成功"节律由记忆系统的计数规则决定（`successes >= 2 且无失败 → warm`），它测的是**这条规则**下的恢复速度，不是普适常数。
7. `scale` 组只到 300 条量级；千条以上的召回仍用子串匹配 + IDF 闸门，未做向量检索，本条不外推。
8. 三组各自只 3 个实体，样本量小，只做行为描述，不做效应量估计。

## 5. 复现

```bash
python "docs/论文/run_host_v3_multiround_study.py" --out <目录> --stage bootstrap
# 每个轮次：--stage recall --round N  → 宿主写决策 → --stage source --round N
#           → 宿主写答卷 → --stage settle --round N
python "docs/论文/run_host_v3_multiround_study.py" --out <目录> --stage report
```

`--stub` 只用于管道自检，结果标 `host_kind = stub`，不得作为宿主结果引用。

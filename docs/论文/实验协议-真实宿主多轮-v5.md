# 实验协议：真实宿主多轮 v5（跨模型复现版本元数据消融）

- 协议号：`host-loop-v5`
- 冻结时间：2026-11-03，**在任何外部模型看到任何一条召回之前**
- 任务种子：`20261103`（与 v4 完全相同，规则、载荷、版本日程逐条一致）
- 装置：`run_host_v5_multiround_study.py`
- 产物：`experiment_results/host-loop-v5-20261103/`

## 0. 为什么做这一档

v2 §9 第 3 条欠账：**跨模型一致性未测**。v1–v4 的宿主都是同一个会话中的模型，且它同时是实验设计者。v4 做出了 75 个百分点的消融差，但无法排除"这个差是这一个宿主的行为习惯"。

本档把宿主换成**外部 API 模型**，任务、记忆、召回呈现层、消费规则全部沿用 v4，只换宿主。外部模型不知道分组构造、不知道假设、不参与设计，因此 v4 的"宿主非盲"这一条在本档被消除（设计者非盲仍在）。

## 1. 宿主与规模

DeepSeek 官方 API 当前提供两个模型，两个都跑：

| 宿主 | 请求 model | 定位 |
| --- | --- | --- |
| `deepseek-v4-pro` | `deepseek-v4-pro` | **真正的跨模型臂**：与会话宿主不同族 |
| `deepseek-flash` | `deepseek-flash` | 同族独立进程臂：宿主日志显示会话模型为 `deepseek-v4.1-flash-1017`，故本臂**不算跨模型**，只用来去掉设计者非盲性 |

响应里的 `model` 字段逐次落盘；若与请求名不一致，以响应为准并在结果中写明。

每个宿主 2 组 × 2 臂 × 3 族 = 12 实体 × 4 轮 = **48 次作答**，两个宿主合计 **96 次作答**。每个宿主各自一个 `BUTIAN_HOME`，由 v4 的 `stage_bootstrap` 以同一确定性流程预置，两库内容逐条相同。

其余设计（drift/stable 两组、gated/naive 两臂、记忆全程停 v1、不写回、不登记实践观察）与 v4 逐字相同。

## 2. 宿主接口与消费规则

宿主拿到的是与 v4 完全相同的两份材料：题面（含"当前文档版本 v{n}"）与该臂的召回呈现层。消费规则用与 v4 第 2 节相同的措辞写进 system prompt：

> 召回给出的经验，若状态为 `warm`/`hot` 且其版本与本轮任务一致 → 据此作答；
> 若召回项**不含任何版本与状态信息** → 按内容直接作答；
> 若版本不一致、或状态为 `candidate`/`disputed` → 读源后作答；
> 三者都不成立 → `unknown`。

流程：

1. 第一次调用：题面 + 召回呈现。模型返回 JSON `{"decision": "experience"|"source"|"unknown", "memory_index": int|null, "rule": object|null, "answer": object|null, "reason": str}`。
2. 若 `decision == "source"`：装置真的调 `butian_knowledge_source_read`，把源全文追加进对话，第二次调用要求模型给出 `rule` 与 `answer`。
3. 判分两条口径分开记：
   - **主口径 `script_verdict`**：装置用**模型选中的那条 `rule`** 在本地算出答案再判分。这与 v4 口径一致（算术由脚本执行），把"选错规则"与"算错数"分开。
   - **副口径 `model_verdict`**：直接判分模型自己给出的 `answer`，用来暴露算术能力这一混淆。
4. JSON 解析失败时以 `temperature=0` 重试一次；仍失败记 `protocol_error`，主副口径均记 `unknown`，并单独计数上报，不静默丢弃。

`temperature=0`，`max_tokens=2000`，非流式。每题的完整请求消息与原始回复落盘到 `models/<model>/calls/`，token 用量逐次记录。

## 3. 判据（跑之前冻结，逐宿主判）

| 编号 | 判据 | 通过条件 |
| --- | --- | --- |
| Y1 | 方向复现 | drift 组 R2–R4（9 题）上，`gated` 主口径正确率 − `naive` 主口径正确率 **≥ 50 个百分点** |
| Y2 | 失效形态仍是沿用旧版本 | `naive+drift` R2–R4 的主口径错题中，`stale_match`（答案精确等于 v1 规则的答案）占比 **≥ 2/3** |
| Y3 | 反假绿 | `stable` 组两臂主口径正确率**各 ≥ 11/12** |
| Y4 | 库未被改动 | 该宿主库内 12 条记忆终态版本仍为 1、状态仍为 `warm` |

逐宿主判词：

- Y1–Y4 全真 → `v5_replicated`
- Y3 假 → `v5_control_failed`（对照臂坏了，Y1 的差不得归因于元数据）
- Y1 真而 Y2 或 Y4 假 → `v5_direction_only`
- 其余 → `v5_not_replicated`

总判词：

- 两个宿主都 `v5_replicated` → `v5_cross_model_replicated`
- 只有 `deepseek-v4-pro` 是 `v5_replicated` → `v5_cross_model_replicated_on_pro_only`（**跨模型结论只由 pro 承担**）
- 只有 `deepseek-flash` 是 `v5_replicated` → `v5_same_family_only`（不构成跨模型证据）
- 其余 → `v5_not_replicated`

## 4. 预注册的子群读数：naive 呈现层不是完全无版本线索

必须提前写死一处装置缺陷：`naive` 臂只抹掉显式的 `version` 字段与 `memory_id`/`status`，**没有**抹掉内容里偶然携带的版本线索——`tool` 族的 `endpoint=/api/v1/...`、`parameter=limit_v1`，`schema` 族的 `flow_field=f1`/`level_field=h1`。一个足够细心的模型可能从这些串里推断出陈旧。

因此预注册一个子群读数：**`calibration` 族**的内容只有 `scale` 与 `offset` 两个纯数值，不含任何版本线索，是三族里唯一干净的消融。逐族正确率必须分族报告；若总判词成立而 `calibration` 子群不成立，结论必须降级为"依赖偶然版本线索"，不得读成纯粹的元数据效应。

## 5. 限制（写在结果之前）

1. 设计者非盲仍在；宿主非盲在本档被消除。
2. `naive` 臂"无元数据即信任内容"仍是写进 prompt 的**建模假设**，不是对真实开源记忆模块的实测。本档测的是"外部模型在既定消费规则下"的行为。
3. 主口径算术由脚本执行；副口径单独报告模型算术，两者不得混引。
4. 漂移日程是协议内设定，不代表真实世界分布。
5. 每个宿主单次运行、`temperature=0`，没有重复采样，不报 p 值；12 条独立规则不能当 48 个独立样本。
6. 不写回，故不回答"能不能学会新版本"。
7. 两个外部模型同属一家厂商，不能外推为"任意模型"。
8. API 返回的实际模型名以响应 `model` 字段为准；厂商可能在同名端点后更换权重，复现时须核对落盘的模型名与日期。

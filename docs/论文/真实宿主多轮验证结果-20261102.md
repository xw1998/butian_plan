## 5. 机制读数（这是本实验真正的产出）

正确率是饱和的（36/36），所以本实验的信息全在**行为**上，而不在精度上：

1. **版本准入是被宿主主动执行的，不是被判分器兜住的。** R2、R3 的漂移实体，召回里都有旧版本记忆
   （`calibration002-v1` 在 R2、`calibration002-v1`+`v2` 在 R3），宿主自己比对内容里的 `version` 字段，
   发现与题面版本不一致才去读源。全程 **0 次沿用旧版本错误**——如果宿主偷懒复用旧规则，这三轮会各错 6 题。
2. **复用的收益出现在第二次独立实践之后，而不是第一次。** 稳定实体在 R2 就能复用（经验已经有一次成功实践），
   于是 R2 起源读取从 6 降到 0；写回又在同一轮把它升成 `warm`，所以 R3 是"复用一条已经 warm 的经验"。
   这与主实验里"两次独立成功才升 warm"的语义完全一致，而且是真实模型在真实调用里跑出来的。
3. **漂移实体的记忆按版本裂成三条，每条永远停在 `candidate`。** 18 条候选记忆各只有一次实践，状态不升；
   这不是缺陷，正是版本化经验的设计：内容一变，旧条目就不再被计入新条目的独立证据。
4. **召回通道有个真实短板。** `butian_memory_recall` 只做子串模糊匹配（查询切成二字组命中 `content`，
   再按状态/权重/更新时间排序），没有按实体或标签的结构化过滤。第一轮用 `limit=10` 时，12 条记忆只回了 10 条，
   而且**恰好漏掉了提问实体本身**——宿主拿到的是一堆别的实体的经验。把 `limit` 提到 50 取回全部再自行过滤后，
   一切正常（见 `summary.json` 的 `channel_notes`）。这一条已登记为本实验暴露的产品短板，见第 7 节。

## 6. 运行前发现并修掉的三处构造缺陷

这三处都在**宿主作答之前**改掉，判据、评分口径、样本量一个没动：

| 缺陷 | 表现 | 处置 |
| --- | --- | --- |
| 规则与轮次绑错 | 稳定实体的三轮各生成一条新的 v1 规则，归档里同一实体同一版本出现 3 条不同 RULE 行，宿主无法判断该用哪条（题面变成不可答） | 规则改为按 `(实体, 版本)` 唯一：稳定实体三轮共用一条，漂移实体每版本一条 |
| 归档没写换算约定 | 归档只有 RULE 数值，`(raw − offset) / scale` 这类公式不在源里，答对只能靠猜 | 在归档头部写明三族的换算约定（公式本身与实体无关，不泄露任何一条答案） |
| 召回无结构化过滤 | 见第 5 节第 4 点 | 宿主改用 `limit=50` 取回全部再自行过滤，参数不改变任何判据 |

前两处如果不修，正确率会掉到 1/3 左右，而掉的原因与"补天有没有用"毫无关系。修掉之后宁可判据不成立，
也不能拿一个题目本身不可答的装置去宣称结论。

## 7. 有效性威胁与不能做的读法

| 威胁 | 说明 |
| --- | --- |
| 非盲 | 宿主同时是实验设计者，知道哪一半是稳定实体、知道 R3 期望复用。只有"客观判分 + 判据事前冻结 + 收回 J 型样本"部分补偿 |
| 天花板 | 36/36 全对，正确率这一轴没有分辨力。P1/P3 的"正确数不下降"是平局成立，不是提升 |
| 单宿主、单次 | 只有一个模型、只跑一次，不报 p 值，不能跨模型外推 |
| 算术由本地脚本执行 | 宿主是真实模型，但每题的四则运算由本地 Python 完成（相当于 agent 用计算器）。本实验证明的是"通道 + 版本准入 + 复用"链路在真实宿主驱动下成立，**不证明模型的推理能力** |
| 合成任务与合成源 | 真值来自 `solve()`，源是单文件归档，不是真实版本化文档库 |
| 未测成本优势 | 不测量 token、延迟、算力；不声称模型参数变化 |

不能做的读法：不能说"模型变强了"、不能说"经验自动归纳出来了"、不能说"跨模型泛化"、不能说"生产环境省钱"。

## 8. 与三项旧实验的关系

| 实验 | 宿主 | 本实验补上的那一格 |
| --- | --- | --- |
| 多轮机制实验（10 种子） | 确定性 `solve()` | —— |
| 端到端门槛实验（20 种子） | 同一个确定性求解器 | —— |
| 同 Agent 试跑（15 条） | 当前模型，单轮、正则打分、上下文注入 | 换成真 MCP 工具、三轮、精确匹配判分 |
| **本实验** | 当前模型 + 真 MCP 工具 + 多轮 + 客观判分 | 补齐"真实宿主"这一格；结论强度仍是 pilot |

四者共用同一套任务族与 `solve()` 真值，所以差异只可能来自"谁来作答、用什么通道、判据有多严"。

## 9. 本实验没有回答的问题

1. 换一个模型会不会同样执行版本准入（需要跨模型，且需要能挂 MCP 的宿主）。
2. 宿主会不会在被召回大量旧版本记忆时**误用**（本实验每个实体的候选版本 ≤ 3，压力不足）。
3. 经验质量对后续作答的影响（本实验写回的都是被判分器确认正确的经验，没有注入坏经验）。
4. 多轮更长时的漂移率、以及"每次版本变更都只有一次实践"是否会让记忆永远停在 `candidate`。

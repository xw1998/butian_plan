# 真实宿主多轮验证结果 v7：让模型自己攒经验，攒得对不对、值不值、会不会被污染（2026-11-03）

- 协议：[`实验协议-真实宿主多轮-v7.md`](实验协议-真实宿主多轮-v7.md)（`host-loop-v7`，任务种子 `20261103`，含修订 r1，跑之前冻结）
- 装置：[`run_host_v7_formation_study.py`](run_host_v7_formation_study.py)
- 产物：`experiment_results/host-loop-v7-20261103/`（`summary.json` + 每臂 `state.json` / `fixtures/` / `stages/` / `calls/` / `mcp-trace.jsonl`；两个 `production/` 运行库与 `evidence/` 不入库）
- 宿主：**外部 API 模型** `deepseek-flash`（DeepSeek-V4.1-Flash），单宿主
- **总判词：`v7_formation_effective`（F1–F5 五条全真）**

## 1. 这一档回答的是「经验是自己攒的」

v4–v6 里，经验库都是**实验者预置**的：120 条记忆、每条两份独立证据、状态 `warm`。模型只负责消费。所以前面几档能证明「有库比没库强」，证明不了**库是自己长出来的还有没有用**。

v7 把库清空（`bootstrap` 后 `memory` 为空），只剩两臂：

| 臂 | 可用工具 | 起点 |
|---|---|---|
| `form` | `butian_memory_recall` + `butian_knowledge_source_read` + `butian_memory_practice` + `butian_memory_revise` | 空库，边干边攒 |
| `noref` | 只有 `butian_knowledge_source_read` | 空库，每题翻手册 |

两臂共用同一份语料、同一任务顺序、同一提示词骨架、`temperature=0`、每题独立上下文。
`noref` 只是少了记忆层，所以它的成本就是「攒经验这件事值不值」的对照线。

## 2. 三轮读数：正确率不掉，读源减半

| 轮次 | 手册陈旧实体 | `form` 读源 | `form` 复用记忆 | `noref` 读源 |
|---|---|---|---|---|
| R1（空库） | 0/24 | 24 | 0 | 24 |
| R2（8 个改版） | 8/24 | **8** | **16** | 24 |
| R3（另 4 个首次改版） | 12/24（相对库仍属未知的 4 个） | **4** | **20** | 24 |
| 合计 | — | **36** | **36/48 = 75%** | **72** |

| 臂 | 正确 | 准确率 | 读源次数 | prompt token | 调用数 |
|---|---|---|---|---|---|
| `form` | 72/72 | **100%** | **36** | **604,974** | 108 |
| `noref` | 72/72 | 100% | 72 | 1,021,179 | 72 |

- 读源：36 vs 72，**省 50%**；只看 R2+R3（库已建起来之后）：**12 vs 48，省 75%**。
- prompt token：降到 59.2%（**省 40.8%**）。省的幅度小于读源幅度，因为 `form` 每次调用都要带上召回结果与写回指令，单次调用更贵；这 0.8 倍溢价记在 §5。
- 正确率：两臂都是 72/72。`form` 没有因为「相信自己攒的记忆」掉分。

## 3. 攒的过程：24 次建档 + 12 次改档，零空转

| 写回动作 | 次数 | 触发条件 |
|---|---|---|
| `practice`（首次建档） | **24** | R1 每题读到源行后按源行建档，`independent_key = src-<实体>-v<版本>` |
| `revise`（改档） | **12** | 手册改版后，库中内容与源行不一致 → 按源行改写，旧版标 `superseded` |
| `unchanged`（内容相同，不动） | 0 | 没有出现「读了源但结论没变」的冗余写回 |
| `skipped` / `error` | **0** / **0** | 没有缺内容、缺证据、被校验拒绝的写回 |

12 次 `revise` 与 12 次漂移题一一对应（R2 8 次、R3 4 次）。也就是说：**手册改了几个实体，库就改了几条，一次不多一次不少**。

状态机走过一遍完整路径：`candidate`（首次建档，confidence 0.2）→ 被后续轮次召回复用 → 改版时 `superseded` + 新版本重新落 `candidate`。

## 4. 复用作证：75% 的题靠记忆答对，且答案与真值逐字相等

- R2+R3 共 48 题里 **36 题**（75%）走的是 `decision="experience"`：召回命中本实体条目、版本一致、状态 ∈ {warm, hot, candidate} → 直接作答，不读源。
- 判分是精确匹配（数值按 3 位小数比对）。36 题全部 `script_verdict=correct`，不是「差不多对」。
- 省下的正是这一类题：库里有、版本对、状态可用。剩下 12 题一律 `decision="source"`——因为版本已经对不上，模型自己认出「这条不能用了」。

## 5. 成本核算：省下的读源 vs 多出的调用

| 项 | `form` | `noref` | 差 |
|---|---|---|---|
| 调用次数 | 108 | 72 | +36（多 50%） |
| prompt token | 604,974 | 1,021,179 | **−416,205（−40.8%）** |
| 单次调用平均 prompt | 5,602 | 14,183 | −60.5% |

调用次数更多是因为 `form` 在 R1 每题要走「申请读源 → 带源作答」两趟；但每趟的上下文小得多（召回结果只有几条），所以总量仍然省 40.8%。

要注意一个**没被省掉的开销**：R1 是纯投入轮——24 题全部要读源、还要额外 24 次 `practice`，这一轮 `form` 比 `noref` 贵（48 次调用 vs 24 次）。收益从 R2 才开始兑现。所以本档的省 50% 是**三轮平均**的数字，单看 R1 是亏的。这一点在论文里必须写清楚，不能拿平均值当「立刻见效」。

## 6. 污染审计：零污染、零陈旧复用

装置**不纠正写回内容**——这是能测污染的充要条件。审计结果：

| 项 | 读数 |
|---|---|
| 污染（写回内容 ≠ 源行） | **0** |
| 陈旧复用（库中版本落后仍直接作答） | **0** |
| 该读源却没读（漏读） | 0 |
| 不该读源却读了（误花） | 0 |

逐题核对口径：R2 的 8 个改版实体、R3 的 4 个，`form` 全部命中 `decision="source"`；其余 36 题 `version` 与库中一致，全部命中 `decision="experience"`。闸门 48/48 逐题正确。

## 7. 判据 F1–F5

| 判据 | 含义 | 读数 | 结论 |
|---|---|---|---|
| F1 | `acc(form) ≥ acc(noref) − 0.05` | 1.0 vs 1.0 | 通过 |
| F2 | R2+R3 读源 `form ≤ 0.5 × noref` | 12 ≤ 24 | 通过（实际 25%） |
| F3 | `acc(noref) ≥ 0.95`（反假绿：基线不能被装置弄瘸） | 1.0 | 通过 |
| F4 | 复用率 `> 0.5` | 36/48 = 0.75 | 通过 |
| F5 | 污染计数 = 0 | 0 | 通过 |

F3 同 v6：`noref` 在不限额时满分，说明基线没被做瘸——手册里答案写得好好的，谁肯翻谁就对。`form` 的优势只体现在「翻手册的代价」上。

## 8. 这说明了什么、不说明什么

**说明**：

1. 经验库**自己攒出来**也能用：空库起步，两轮之后 75% 的题靠自建记忆答对，正确率不掉。
2. 攒的过程是干净的：24 次建档 + 12 次改档，与手册的实际变更一一对应，零空转、零污染、零陈旧复用。
3. 自建库同样把读源压到一半（R2+R3 压到 25%），prompt token 压到 59.2%。
4. 模型能自己认出「这条记忆已经不可信」——版本不一致就转去读源，而不是硬用旧值。

**不说明**：

1. **只有单宿主、24 个实体、3 轮**。跨模型已由 v6 覆盖（两宿主读数逐格相同），但「形成」这件事只有一个模型一个种子。
2. **R1 是净投入**：建库那一轮比不建库更贵（48 次调用 vs 24 次）。本档的「省」是三轮平均，不能读成「一上手就省」。
3. **允许「自抄 candidate」复用**（协议 §7.7 的建模设定）：补天默认规则要求 candidate 复核转 warm，而同一份源读两遍不构成独立证据（会被 `independent_evidence_required` 拒），若强按默认走，形成成本会吃掉全部收益。代价由 F5 污染判据兜。这条是设定，不是补天的默认行为。
4. **证据身份由源行决定**：装置为每个 (实体,版本) 的 RULE 行单独登记证据件，写回用真实 `ev_*`。因此「换版本即换证据」是装置保证的，不构成模型能力。
5. 语料仍是合成手册、条目单一、取值唯一；没测「标记错了」（假阴性/假阳性）、没测冲突消解、没测多轮指代。
6. 每题独立上下文，`noref` 的读源成本被高估（真实 agent 会缓存手册），偏差方向对 `noref` 不利。

## 9. 运行质量与复现

运行质量：`parse_errors=0`，`served_models` 逐轮核对均为 `deepseek-flash`，两臂无人工干预、无重试改写答案。

跑的过程中官方接口在 17:49–17:56 出现间歇 `HTTP 503`，导致首轮中断；装置因此加了两处纯工程加固（不影响协议与读数）：

- `install_resilient_api()`：503/429/5xx/网络异常退避重试 8 次、单次上限 45 s；
- 逐题断点 + `--stage auto`：每结算一题即落盘，崩溃后按 `entity` 去重续跑。

`models/*/calls/r{1,2,3}-<臂>/` 下保留了逐题原始调用与 `_checkpoint-r{N}.jsonl`（含完整 messages 与 usage），可逐格复核。

```bash

python docs/论文/run_host_v7_formation_study.py --out "$OUT" --stage auto --arm form

```

已结算的题自动跳过（幂等）；`--stage auto` 含断点续跑与退避重试。

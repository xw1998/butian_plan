# 补天计划经验机制实验协议

## 研究问题

经验生命周期、证据约束、版本演化和上下文恢复是否能提升 AI Agent 的问题解决能力，同时减少无依据断言和上下文黑洞？

## 对照组

- B0：仅使用当前会话上下文，不启用长期经验机制。
- B1：启用长期记忆检索，但不启用强化、证伪、版本演化和做梦。
- B2：启用补天完整机制，包括经验/教训、证据、冲突、版本、恢复和做梦候选。

三个条件必须使用相同的任务包、工具权限、模型/Provider、最大调用预算和随机种子；无法固定时将模型和 Provider 作为分层因素报告。

## 任务集

任务集必须版本化并哈希固定，至少包含：重复问题、新问题迁移、冲突证据、外部论文转实践、长会话压缩恢复。每个任务包含目标、约束、工具权限、验收标准、隐藏参考答案、允许的证据和风险等级。

## 指标

首次解决率、重复问题解决率、迁移成功率、尝试次数、耗时、模型调用数、成本、失败复发率、上下文黑洞次数、无依据断言率、`unknown` 诚实率、抽象到具体经历召回率、外部主张转本地经验率、人工审核负担、取消恢复成功率。

上下文黑洞定义为：所需信息已存在于事件日志或快照中，但当前 Agent 未召回，或召回后无法正确使用。每次发生必须记录任务 ID、信息 ID、应有层级、实际上下文和证据。

## 可复现记录

每次运行保存：任务包哈希、数据集版本、代码 commit、配置、模型/Provider 版本、操作系统、随机种子、预算、原始事件日志、统计脚本、失败样本和最终报告。报告均值、离散程度和置信区间，不只报告最佳结果。

## 论文结论边界

结论只适用于记录的任务、模型、Provider、工具和版本。外部论文和网页只能形成 `source_knowledge` 或 `practice_hypothesis`，必须经过本地实验才可升级为本地经验。

## 同一宿主Agent内比较：修订协议

用户确认：补天依附宿主AI应用，实验在一个Agent中比较，不需要独立模型服务或新的模型会话。B0/B1/B2是同一Agent的机制条件消融，不是三个独立模型。宿主、模型能力与工具预算保持一致；无法观测的模型版本和费用保留null。

按任务配对轮换顺序：种子1103对应B0→B1→B2，2207对应B1→B2→B0，3301对应B2→B0→B1。种子仅标识工具随机性和计划顺序，不能宣称宿主模型随机种子已受控。每个条件使用独立的补天数据命名空间；切换机制不能擦除模型已经读过的信息。保存先前答案可见性、条件顺序和记忆携带状态，已知参考答案的运行记为非盲测。

同会话比较是有效的工程消融设计，但样本存在顺序、熟悉度和上下文携带影响；结果按case和顺序配对作描述性报告，不把45个输入视为45个独立样本，不以普通独立样本区间声称因果优势。不要求通过独立模型实验才能交付研究。此前0.1.4尚未实际执行B0/B1/B2的历史事实保持不变。


## 执行状态修正

本研究不支持也不要求独立模型。目标是同一宿主 Agent 内的条件消融：相同任务包、相同宿主模型和工具权限，分别关闭长期经验（B0）、只启用固定检索（B1）和启用完整补天机制（B2）。当前仓库已完成协议、顺序轮换和记录字段实现；真实 Agent 条件运行需要由宿主调度当前 Agent 执行，仓库脚本本身只负责准备输入和保存结果，不能把自身脚本运行冒充 Agent 回答。

## 五项命题新增实验协议

1. 容量与隐含信息：使用同一任务集、等价提示和多规模模型，测量关系保持率、事实保持率和改述鲁棒性；参数量只作为自变量之一，不能直接代替互信息。
2. 监督与幻觉：固定事实问题集，分离交叉熵、指令监督、偏好监督和证据约束，分别报告事实正确率、无依据断言率、拒答校准和文本流畅性。
3. 涌现：同时报告连续能力分数与阈值通过率，控制提示、解码和评测选择，至少使用多个规模和多个随机种子。
4. 逻辑闭环：以事件链、证据来源、版本冲突和恢复状态为验收对象；运行期记忆有效不等于参数更新有效。
5. 持续进化：分开测量运行期检索、经验数据集筛选和真正后训练。只有保存训练前后模型版本、固定评测、遗忘率、幻觉率和回滚结果，才能声称参数持续进化。

新增合成控制脚本为 `run_evolution_controls.py`，输出目录为 `experiment_results/evolution-controls-20261015-r2/`。该实验只验证有限容量玩具模型、监督标签噪声和任务覆盖公式，不训练神经模型、不修改权重。


## 同类校准任务成本实验

脚本 `run_same_family_benefit.py` 实际运行24个配对合成校准任务：三组使用相同版本感知求解器与同一原始资料权限。B0扫描9份档案，B1先读固定旧版记忆再回退，B2实际调用生产上下文召回后求解。三组均24/24正确，在线数据访问为216/240/24；B2相对B0减少88.89%，但本地平均耗时增加，不能宣称时延下降。B2在本实验中仅启用版本匹配的生产召回路径，不构成完整生命周期消融。该结果是机制基准而非真实宿主模型端到端收益。固定旧版B1也不代表所有固定检索方法，不能外推为B2普遍优于更新后的索引检索。

未采用试写的 `score_within_agent_pilot.py` 及其关键词评分结果：规则受到措辞影响，且无法证明任务完成，故不作为论文证据或正式提交内容。


## 多轮版本约束经验机制主实验（2026-10-15）

本协议对应 `run_multiround_study.py` 与结果目录 `experiment_results/multiround-ieee-20261015-r2/`。研究对象是 ButianService 生产记忆路径与版本约束宿主策略，执行器为同一个确定性求解器，`llm_inference_calls=0`。它隔离机制贡献，不构成自由文本大模型实验。

主实验使用10个种子、12个实体、12轮和7个条件，每条件1440题、总计10080执行。任务族为校准、版本字段迁移和工具参数适配。第5、9轮以0.5概率进行实体语义漂移，第6、7轮以0.25概率令来源不可用，第8轮正常关闭后重开服务。任务输入、档案和时序在条件间共享，各条件使用独立经验库；先记录首次答案，再评分和反馈。只有实际读取来源成功才允许写入经验；来源不可用且无合法经验返回 `unknown`。

条件为 B0-scan、B0-index、B1-static、B2-full、A-no-version、A-no-write、A-no-persist。正确、错误、unknown互斥。统计按10个种子聚类，10000次配对bootstrap给出百分位95%区间；相关轮次不能当独立样本。一次 `W` 定义为一个逻辑验证提交，即事件追加与经验版本写入的组合。

先行5种子pilot在主协议前执行并保留；因此主实验不是无探索预注册。实验不发送真实远程工具请求，不修改模型参数，不将运行期数据库经验称为模型训练。图表中的成本阈值使用明确假设单位权重，不能解释为真实金额或网络延迟。

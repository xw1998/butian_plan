# 实验协议：真实宿主多轮 v4（连续漂移与版本元数据的消融对照）

- 协议号：`host-loop-v4`
- 冻结时间：2026-11-03，**在宿主看到任何一轮召回结果之前**
- 随机种子：`20261103`
- 装置：`run_host_v4_multiround_study.py`
- 产物：`experiment_results/host-loop-v4-20261103/`

## 0. 为什么做这一档

前两档真实宿主实验（v1 36 题、v3 36 题）几乎全对，论文 §VII.D 已如实写明：**它们只提供行为读数，不提供精度差异**。一个"全都答对"的实验无法说明机制是不是在承重——把机制拆掉可能同样全对。本档补两件事：

1. **消融对照**：同一批任务、同一套记忆、同一个宿主消费规则，只改"召回是否携带版本与状态元数据"，看正确率会不会掉。掉了才说明这层元数据在承重。
2. **连续漂移**（v2 §9 第 4 条，此前未答）：源文档每轮 +1 版，记忆停在 v1，问宿主会不会偷懒沿用旧版本。

本档**不**回答跨模型一致性（v2 §9 第 3 条），那需要换模型重跑，仍是欠账。

## 1. 设计

2 组 × 2 臂 × 3 族 = 12 个实体，每实体 4 轮，共 **48 次作答**。

| 组 | 源版本日程 | 问什么 |
| --- | --- | --- |
| `drift` | 第 n 轮用 v(n)，v1→v4 每轮都变 | 记忆停在 v1 时会不会被继续沿用 |
| `stable` | 四轮都是 v1 | 反假绿：没有漂移时两臂是否都对 |

| 臂 | 召回给宿主看什么 | 对应现实中的什么系统 |
| --- | --- | --- |
| `gated` | 补天原样返回：`memory_id`（带版本后缀）、`status`、`content`（内含 `version` 字段） | 带准入元数据的经验库 |
| `naive` | **只给 `content`，且抹掉其中的 `version` 字段**；不给 `memory_id`、`status`、`needs_revalidation` | 只存文本的记忆模块（检索到就塞进上下文） |

两臂共用**同一个** butian 库、**同一批**记忆（都在 v1 上以两条独立成功预置为 `warm`），差别只在召回呈现层。实体编号 `{family}{suffix}01`：suffix 1=drift/gated、2=drift/naive、3=stable/gated、4=stable/naive。

三族沿用 v1–v3 的契约化任务：`calibration`（`(raw-offset)/scale`）、`schema`（`payload[flow_field]/divisor` 与 `level`）、`tool`（端点/参数名/`raw*factor`）。漂移时三族的参数都真的变：`schema` 的字段名随版本变成 `f{n}`/`h{n}`，`tool` 的端点与参数名随版本变成 `/api/v{n}/...`、`limit_v{n}`。

## 2. 宿主消费规则（两臂同一条，冻结）

> 召回给出的经验，若状态为 `warm`/`hot` 且其版本与本轮任务一致 → 据此作答；
> 若召回项**不含任何版本与状态信息** → 按内容直接作答；
> 若版本不一致、或状态为 `candidate`/`disputed` → 读源后作答；
> 三者都不成立 → `unknown`。

第二个分支是**朴素消费者的建模假设**：只存文本的记忆模块，其消费者检索到内容就直接用。它不是对"所有消费者都会这样"的断言，见 §4 限制第 2 条。

宿主只做三件事：`butian_memory_recall`、`butian_knowledge_source_read`、提交答案。本档**不做任何经验写回、不做任何实践观察登记**——记忆全程停在 v1，把"漂移"这一个因素单独隔出来。

## 3. 判据（跑之前冻结）

| 编号 | 判据 | 通过条件 |
| --- | --- | --- |
| K1 | gated 臂承重 | 24 题全对；`drift` 组 R2–R4 共 9 次读源，`stable` 组 0 次读源 |
| K2 | naive 臂在漂移下失效，且失效形态是"沿用旧版本" | `naive+drift` 自 R2 起每轮 3 题全错（共 9 错），读源 0 次，且**每个错答精确等于用 v1 规则算出的答案**（`stale_match` 9/9） |
| K3 | 反假绿：naive 臂不是"本身就坏" | `stable` 组两臂各 12 题全对 |
| K4 | 漂移没有把旧记忆洗白 | gated 臂 `drift` 实体的记忆终态版本仍为 1、状态仍为 `warm`，四轮不变 |

判词：

- K1–K4 全真 → `v4_version_metadata_load_bearing`
- K1、K3、K4 真而 K2 假 → `v4_ablation_inconclusive`（拆掉元数据也没掉正确率，本装置无法证明承重）
- K3 假 → `v4_control_failed`（对照臂本身坏了，K2 的差异不得归因于元数据）
- 其余 → `v4_not_confirmed`

K2 的 `stale_match` 是关键：只有"错答 == v1 规则的答案"才叫沿用旧版本；随机答错不算。

## 4. 限制（写在结果之前）

1. 宿主同时是实验设计者，非盲；消费规则预注册并冻结，但这不消除非盲性。
2. `naive` 臂的"无元数据即信任内容"是建模假设。结论只能读成"**在信任召回内容的消费者下**，版本元数据承重"，不能读成"任何消费者用了朴素记忆都会错"。
3. 四则运算由本地脚本执行，不是模型推理能力的证据。
4. 漂移日程是协议内设定（每轮必变），不代表真实世界的版本变化分布。
5. 单种子、单次运行，没有跨模型、跨运行的重复。
6. 记忆全程不写回，因此本档不回答"漂移后能不能追上新版本"，只回答"会不会沿用旧版本"。
7. 12 个实体是 12 条独立规则，但同一族的三族公式共享，不能把 48 题当 48 个独立样本。
8. `naive` 臂的呈现层由 harness 构造，不是另装一个开源记忆模块；它模拟的是"只返回文本"这一接口形态。

## 5. 复现

```bash
cd docs/论文
OUT=D:/工作/git_project/butian_plan/docs/论文/experiment_results/host-loop-v4-20261103
python run_host_v4_multiround_study.py --out "$OUT" --stage bootstrap
for r in 1 2 3 4; do
  python run_host_v4_multiround_study.py --out "$OUT" --stage recall --round $r
  # 宿主按第 2 节规则写 stages/r$r-recall-decision.json
  python run_host_v4_multiround_study.py --out "$OUT" --stage source --round $r
  # 宿主写 stages/r$r-answers.json
  python run_host_v4_multiround_study.py --out "$OUT" --stage settle --round $r
done
python run_host_v4_multiround_study.py --out "$OUT" --stage report
```

`--out` 必须传绝对路径：装置内相对路径会以 `docs/论文` 为基准拼接。`--stub` 只用于管道自检，产物标 `host_kind=stub`，不得作为宿主结果引用。

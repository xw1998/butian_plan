# 实验协议 v7：形成侧有效性（宿主自己攒经验，2026-11-03 冻结）

- 协议名 `host-loop-v7`，任务种子 `20261103`（与 v6 共用同一套语料构造）
- 宿主：**只用 `deepseek-flash`**（DeepSeek-V4.1-Flash）。刻意不用 pro：本档的自变量是
  「形成链有没有用」，不是「换模型结论还成不成立」；跨模型那一条已由 v6 覆盖。
- 跑之前冻结本文件；任何判据、语料、口径改动都必须在结果文档里单独登记，不得静默修改。

## 1. 这一档补的是 v6 留下的那句「经验从哪来」

v6 证明的是「库里已经有可靠经验时，用它比不用强」：读源省 72.2%，同额度完成量 2–3 倍。
但 v6 的 120 条经验是实验者预置的。真实使用中没人替它预置，经验要靠宿主自己边干边攒。
本档把库清空，从零开始，问三件事：

1. 自己攒的经验，后面还认不认得出来（复用它省不省读源）？
2. 攒的过程本身要花代价（写回调用、额外 token），这代价会不会把收益吃掉？
3. 攒错了怎么办——把错误结论写进库，后面会不会照着错的答（污染）？

## 2. 语料与任务

- 完全复用 v6：327 行 / 38,063 B 合成手册，120 实体 × 1–4 版本，24 个任务实体（每族 8 个）+ 96 个诱饵。
- 任务：**24 个任务实体 × 3 轮 = 72 题**，同一实体在轮间重复出现，这才有「第二次不用翻手册」的机会。
- 漂移日程同 v6 冻结口径：R1 全为 v1；R2 有 8 个实体改到 v2；R3 这 8 个仍是 v2、另加 4 个首次改到 v2。
  改版强制重抽参数，保证旧版本答案不等于真值。
- 题面照旧给出「当前文档版本 vN」，与 v4–v6 一致；版本判断不是本档的自变量。

## 3. 两臂

| 臂 | 起始库 | 可用工具 | 说明 |
|---|---|---|---|
| `form` | **空** | `memory_recall` + `knowledge_source_read` + `memory_practice` + `memory_revise` | 边干边攒；每读完源就地沉淀 |
| `noref` | 不使用 | 只有 `knowledge_source_read` | 每题翻手册，不写不记 |

两臂共用同一语料、同一题序、同一提示词骨架、`temperature=0`、每题独立上下文。

## 4. 形成规则（写进 form 臂提示词，装置代执行工具调用）

1. 先召回：`memory_recall(query=实体名 + 族, limit=20)`，得到条目（含 `status`、`content`、`needs_revalidation`）。
2. 决策：召回条目明确给出与本轮版本一致的规则，且状态为 `warm`/`hot`/`candidate` → 直接作答；
   版本不一致、状态 `disputed`、或 `needs_revalidation=true` → 读源。

   **与本项目前几档的口径差异（必须登记）**：v4–v6 的消费规则要求 `candidate` 必须先复核，
   因为那种 candidate 是**上游或对端主张**，没经过本宿主验证。本档的 candidate 是宿主自己
   上一轮从源文档抄下来的东西，证据就是源行本身，性质不同。因此本档允许这种「自抄 candidate」
   直接复用。理由与代价都写死在这里：允许复用才可能省读源，但一旦抄错就会形成污染，
   这正是 F5 要抓的东西。
3. 写回：凡依赖源文档作答，必须提交 `memorize` 字段：
   - `memory_id` 固定为实体名；
   - `content` 必须是源文档里该实体、**本轮版本**的那条 RULE，原样抄；
   - 装置发现该实体已有不同内容时调 `memory_revise`（带本次源行哈希），否则调 `memory_practice`
     （`independent_key = src-<entity>-v<version>`，`evidence_ref = manual:<entity>:v<version>:<源行哈希前 8 位>`）。
4. 写回内容**原样入库，装置不纠正**——这是能测「污染」的前提。

## 5. 判据（预注册）

| 判据 | 定义 | 含义 |
|---|---|---|
| F1 | `acc(form) ≥ acc(noref) − 0.05`（72 题合计） | 攒着用不能比不用更差 |
| F2 | `reads(form, R2+R3) ≤ 0.5 × reads(noref, R2+R3)` | 第二、三轮读源至少省一半（noref 为 48 次 → 门槛 24） |
| F3 | `acc(noref) ≥ 0.95` | 反假绿：对手不能被装置弄瘸 |
| F4 | `reuse(form, R2+R3) ≥ 0.50` | 复用是真的：本轮零读源、依据为记忆、且答对 |
| F5 | `contamination(form) == 0` | 自己攒的坏经验不得产生错答 |

## 6. 判词

- F1–F5 全过 → `v7_formation_effective`
- F1/F3/F5 过，F2 或 F4 不过 → `v7_formation_reuse_weak`
- F1 不过 → `v7_formation_regressed`
- F3 不过 → `v7_baseline_handicapped`
- 仅 F5 不过（其余全过）→ `v7_formation_effective_with_contamination`，污染题数与位置单独列出

## 7. 预注册的边界与口径

1. **写回内容由模型生成、装置不纠正**：这是测污染的必要条件，代价是可能写入格式不合规的内容；
   装置只判「这条记忆能否让下一轮答对」，不判「写得漂亮」。
2. **证据 ref 由装置按源行计算**（该实体该版本 RULE 行的哈希），不是模型的判断；因此 F5 只测
   「内容层面的污染」，不测「证据层面的伪造」。
3. **只跑 flash 单模型**：跨模型已在 v6 覆盖；本档样本是 24 实体 × 3 轮，不报 p 值。
4. **只测形成链到「能复用」为止**：不测第二次独立验证转 `warm` 的完整生命周期（同实体同版本不会
   重复读源），不测多成员协作、不测跨会话重启（重启另见 v1 的持久化档）。
5. **每题独立上下文**：不放宽；noref 的读源成本因此被高估，偏差方向对 noref 不利，与 v6 一致。
6. 本档不写「整体工具万能」的结论：语料仍是合成手册，条目单一无歧义。
7. **「自抄 candidate 可复用」是本档的建模设定**，不是补天的默认规则：默认规则要求 candidate
   复核后转 warm。本档之所以放宽，是因为这里的 candidate 自带源行证据、且来源是本宿主自己；
   若把它按默认规则处理，一个实体要读两遍源才有资格复用，形成成本会吃掉全部收益，
   而「读两遍同一份源」也不构成两条独立证据（补天会拒绝 `independent_evidence_required`）。
   这条设定把结论范围限死为：**宿主自己从源文档抄录的候选，可以直接复用**。

## 9. 修订 r1（2026-11-03，实施前登记，不涉及判据）

实施时发现 §4/§7.2 的「evidence_ref 由装置按源行计算」与补天的证据校验冲突：
`butian_memory_practice` 与 `butian_memory_revise` 都会先调 `verify_evidence`，
未登记的字符串 ref 一律返回 `practice_evidence_not_valid` / `revision_evidence_not_valid`。

因此改成：**装置在 bootstrap 时把每个 (实体, 版本) 的那一行 RULE 单独落成一个证据件
（正文就是源行，文件名带该源行 sha256 前 8 位），登记后得到真实 `ev_*` 证据 id**，
形成臂写回时使用该 id。口径不变的部分：「证据身份由源行决定」——同一实体换版本即换 ref，
`revise` 的独立性检查因此仍能通过；映射表落 `fixtures/evidence-map.json`，可逐条复核到源行。
判据 F1–F5、两臂定义、语料、模型均不变。

## 10. 修订 r2（2026-11-03，提示词歧义修复后重跑，不涉及判据）

首次全量跑在 `form` 臂 R1 就暴露一个问题：24 题里有 13 题模型直接答 `unknown`，只有 11 题去读源。
查调用记录，模型给出的理由是「召回条目是 calibration001 的 RULE，实体与本次任务的 calibration002
不一致，无法套用，且**无 calibration002 的源规则可读**」——它以为读源是「碰运气能读到」，
而不是「一定能把整本手册读下来」。原提示词的三条规则也没有覆盖「召回里有别的实体的条目」这种情形，
模型于是选了 `unknown`。这属于提示词歧义，不是被测对象的表现。

修法（只改 `form` 臂提示词，判据、语料、两臂定义、模型均不变）：
- 决策规则改成按序判、命中即止的五条，明确「召回里没有**本实体**条目 → 读源」，
  「别的实体/别的族的条目都不算依据」；
- 明确写出「系统会一次把手册全文交给你，读源不是可能读不到」，
  并把题面「没有可用依据必须答 unknown」限定为「不能读源」的场合；
- 只有源文档里确实找不到该实体本轮版本那一行，才允许 `unknown`。

第一次跑的产物（`form` R1 11/24 读源、`noref` R1 24/24）全部作废、清空重跑，
不进入任何读数；`form` 的记忆库从空库重新起算。

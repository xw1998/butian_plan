# 真实宿主多轮验证结果 v6：经验库「用 vs 不用」的双轴有效性（2026-11-03）

- 协议：[`实验协议-真实宿主多轮-v6.md`](实验协议-真实宿主多轮-v6.md)（`host-loop-v6`，任务种子 `20261103`，跑之前冻结）
- 装置：[`run_host_v6_effectiveness_study.py`](run_host_v6_effectiveness_study.py)
- 产物：`experiment_results/host-loop-v6-20261103/`（`summary.json` + 每宿主 `state.json` / `fixtures/` / `stages/` / `calls/` / `mcp-trace.jsonl`；两个 `production/` 运行库与 `evidence/` 不入库）
- 宿主：**外部 API 模型**，两个跨族宿主
  - `deepseek-v4-pro`（DeepSeek-V4-Pro，与会话宿主不同族）
  - `deepseek-flash`（DeepSeek-V4.1-Flash，与会话宿主同族）
- **总判词：`v6_cross_model_replicated`（两个宿主各自 `v6_library_effective_both_axes`，Z1–Z4 全真）**

## 1. 这一档回答的是「用 vs 不用」

v1–v5 回答的是「补天里的某个元件是否承重」：把召回、版本元数据、呈现层逐个拆掉，看正确率掉不掉。这些实验都默认双方还在用经验库，所以只能证明**元件必要**，证明不了**整体上比不用更好**——因为满分是天花板，拆零件掉的分只能说明零件有用。

v6 换问法，直接对比两个真实工作流：

| 臂 | 可用工具 | 说明 |
|---|---|---|
| `lib` | `butian_memory_recall` + `butian_knowledge_source_read` | 先查经验库，只在记忆不可信时去翻原文档 |
| `noref` | 只有 `butian_knowledge_source_read` | 完全没有经验库，每题只能翻原文档 |

`noref` 才是真正的「不用」。此前 v4/v5 的 `naive` 臂本身也在用经验库，所以从来没测过「不用会怎样」。

## 2. 装置与语料（跑之前冻结）

- **语料**：一份 327 行 / 38,063 B 的合成设备手册，覆盖 3 个族（`calibration` 标定、`schema` 协议、`tool` 工具），每族 40 个实体，共 **120 个实体**；每实体 1–4 个版本行。
- **任务**：每族 8 题 × 3 族 = **24 题**；其余 96 个实体是诱饵，两臂都不知道哪些会被问。
- **经验库预置**：全部 120 条都写入，每条 2 份独立证据，状态 `warm`。因此召回不是金手指——有可能召回到诱饵，也有可能召回到旧版本。
- **漂移日程（三档，逐轮推进）**：R1 全 v1（0/24 陈旧）；R2 让 8 个实体的手册值改成 v2（8/24 陈旧）；R3 这 8 个仍是 v2，另加 4 个首次改版（12/24 陈旧）。改版时强制重抽参数，保证「沿用旧版本」与「正确答案」不同值。
- **两臂共用**：同一语料、同一任务顺序、同一提示词骨架、`temperature=0`、每题独立上下文（不跨题缓存）。
- **轴 A（成本）**：三轮不限额，比「同样的正确率要花多少次读源、多少 token」。
- **轴 B（预算）**：每臂每轮只有 `L ∈ {6, 12}` 次读源额度，共 24 题，比「同等预算下能干完多少活」。

## 3. 轴 A：正确率不掉，读源次数降到 27.8%

| 宿主 | 臂 | 正确 | 准确率 | 读源次数 | prompt token | 调用数 |
|---|---|---|---|---|---|---|
| pro | `lib` | 71/72 | **98.6%** | **20** | **335,918** | 92 |
| pro | `noref` | 72/72 | 100% | 72 | 1,054,132 | 74 |
| flash | `lib` | 72/72 | **100%** | **20** | **331,183** | 92 |
| flash | `noref` | 72/72 | 100% | 72 | 1,021,611 | 72 |

- 读源次数：`1 − 20/72 = 72.2%` 省下来，两个宿主完全相同（因为该不该读由冻结的漂移日程决定，不由模型心情决定）。
- prompt token：pro 降到 31.9%（省 68.1%），flash 降到 32.4%（省 67.6%）。
- 唯一一次失手：pro 在 R3 的 `schema005` 上读了源但返回 `unknown`（`model_verdict=correct`，脚本判 `unknown`）。这是模型的输出格式抖动，不是记忆层问题，两个宿主唯一的差异点。

## 4. 轴 B：同等读源预算，完成量差 2–3 倍

| 宿主 | 额度 L | `lib` 完成 | `noref` 完成 | 差 |
|---|---|---|---|---|
| pro | 6 次 | **18/24 = 75.0%** | 6/24 = 25.0% | **+50.0 pp** |
| pro | 12 次 | **24/24 = 100%** | 12/24 = 50.0% | **+50.0 pp** |
| flash | 6 次 | **18/24 = 75.0%** | 6/24 = 25.0% | **+50.0 pp** |
| flash | 12 次 | **24/24 = 100%** | 12/24 = 50.0% | **+50.0 pp** |

读法很直接：**`noref` 每翻一次手册只能答一道题，额度用完就干不了活**（6 次 → 6 题，12 次 → 12 题，一一对应）。`lib` 则把额度只花在「记忆里是旧版本」的那几道题上：

- L=6：`lib` 恰好挑了 6 个陈旧实体读源，18 题直接靠记忆答对；剩下 6 题需要读源但额度已尽 → 返回 `unknown`（不猜）。
- L=12：12 个陈旧实体全覆盖，24/24 全对。

两个宿主、两档额度，读数逐格相同。这不是巧合，而是装置设计的结果：**陈旧集合由手册决定，不由模型猜**；模型要做的事只有一件——认出「记忆里这条已经不可信了」。

## 5. 判据 Z1–Z5 逐条

| 判据 | 含义 | pro | flash |
|---|---|---|---|
| Z1 | `acc(lib) ≥ acc(noref) − 0.05` | 0.9861 vs 1.0 → 通过 | 1.0 vs 1.0 → 通过 |
| Z2 | `reads(lib) ≤ 0.5 × reads(noref)` | 20 ≤ 36 → 通过 | 20 ≤ 36 → 通过 |
| Z3 | `acc(noref) ≥ 0.95`（反假绿：基线不能被装置弄瘸） | 1.0 → 通过 | 1.0 → 通过 |
| Z4 | 存在某档 L 使 `acc(lib) − acc(noref) ≥ 15 pp` | L6/L12 都 +50 pp → 通过 | 同 → 通过 |
| Z5 | 不写回经验库（本档只测消费） | 未写回 | 未写回 |

Z3 是本档最该先看的一条：`noref` 在不限额时是满分。这不是「基线太弱」，恰恰说明装置没有把对手做瘸——手册里答案写得好好的，谁肯翻谁就对。`lib` 的优势只体现在「翻手册的代价」上，这正是要测的东西。

## 6. 闸门审计：零误花、零漏读、失败形态是报错

把「该不该读源」当成一个二分类闸门，对着冻结的陈旧标记逐题核：

| 轮次 | 陈旧题数 | `lib` 实际读源 | 误花（不该读却读） | 漏读（该读却没读） |
|---|---|---|---|---|
| R1 | 0/24 | 0 | 0 | 0 |
| R2 | 8/24 | 8（就是那 8 个） | 0 | 0 |
| R3 | 12/24 | 12（就是那 12 个） | 0 | 0 |

两个宿主都是 24/24 逐题正确判断。更值得注意的是失败形态：L=6 时额度用尽、记忆又是旧版本的 6 道题，`lib` 全部返回 `unknown`，**没有一次瞎猜**。同样地，`noref` 在额度耗尽后也全部返回 `unknown` 而不是编数字。

也就是说，本档 `noref` 输的不是「答错」，而是**停工**——25% 与 50% 是「能干完的比例」，剩下的是明确说「我做不了」。这符合补天「宁可报错不给错答案」的要求，也让「增强」的含义更诚实：**配了经验库，同样预算下能干完的活是 3 倍与 2 倍，而不是把错的改对**。

## 7. 两个宿主的一致性

- 判词一致：两个宿主都是 `v6_library_effective_both_axes` → 总判 `v6_cross_model_replicated`。
- 逐格读数一致：轴 A 读源 20/72，轴 B 四个组合的完成数 18/6/24/12，完全相同的四组数字。
- 差异只有一处：pro 在 R3 `schema005` 上输出格式抖动被判 `unknown`。
- 跨族与同族宿主没有出现方向性差异 ⇒ 结论不是「某个模型的习惯」，而是**任务结构 + 记忆层能力**决定的。

运行质量：`parse_errors=0`，所有调用都由目标模型服务（`served_models` 逐轮核对），两臂均无人工干预，无重试改写答案。

## 8. 这说明了什么、不说明什么

**说明**：

1. 补天的经验库在「不限额度」时把读源次数压到 27.8%、prompt token 压到 32%，正确率不变。
2. 在「额度稀缺」时，同样预算能干完的活是 3 倍（L=6）与 2 倍（L=12）。这是第一次直接测到「用 vs 不用」的差，而不是「拆零件掉多少分」。
3. 该省的地方省、该读的地方读：闸门 24/24 逐题正确，零误花零漏读；省不出来时选择报错而不是猜。
4. 两个跨族宿主复现同样的读数，结论不依赖单一模型。

**不说明**：

1. 语料是合成手册，条目单一、取值唯一、无歧义。真实文档有歧义、有冲突、有缺页，本档没有覆盖。
2. 陈旧标记 `needs_revalidation` 是补天自己算出来的。本档没注入「标记错了」的情形（假阴性=该报不报、假阳性=不该报乱报）。标记一旦不可靠，闸门的 24/24 就会退化成误读或漏读，这一步没测。
3. 每题独立上下文：`noref` 的读源成本被高估了（真实 agent 可能缓存手册），这个偏差方向对 `noref` 不利，已在协议 §8 登记。
4. 每档只有 24 题。50 pp 的差距远超噪声，但绝对数值依赖语料构造（题目难度、漂移比例），不可外推成任意任务上的百分比。
5. 只测消费，不测写回；不测多轮对话指代；不测记忆污染与冲突消解；召回每题只命中 1 条，是理想情形（limit=20 远未用满）。
6. 两个宿主同属 DeepSeek 家族，只做到「同族 + 跨族」两个点，不能外推为任意厂商模型。

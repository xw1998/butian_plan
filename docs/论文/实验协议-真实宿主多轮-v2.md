# 实验协议：真实宿主多轮交互 · 压力档（host-loop v2）

- 冻结时间：2026-11-02，`written_before_execution = true`
- 协议版本：`host-loop-v2`
- 状态：**预注册**。本文件在任何宿主作答之前写成，判据、评分口径与样本量在运行中不得修改；如需修改必须另立 `host-loop-v2.1` 并保留本文件。
- 前置：`实验协议-真实宿主多轮.md`（`host-loop-v1`）与 `真实宿主多轮验证结果-20261102.md`。

## 1. 为什么要做这一档

`host-loop-v1` 的结果是 36 次作答 **36 正确 / 0 答错**，五条判据全成立。但正因为全对，它**没有分辨力**：

| v1 的读数 | 为什么不能当证据用 |
| --- | --- |
| 稳定实体 R2/R3 读源 0 次仍全对 | 记忆内容本身就正确（写回用的就是判分后的真值），复用正确只能说明"抄对了" |
| 漂移实体旧版本错误 0 次 | 每个实体同版本只有 ≤3 条候选，且 `make_rule` 把版本号写进了字段名/端点名（`f{version}`、`/api/v{version}/`），**版本靠肉眼就能认**，不算真的压力 |
| 36/36 正确 | 没有注入任何坏经验，等于只测了"正确经验会不会被用"，没测"错误经验会不会被识破" |

v2 只加两个压力轴，其余口径与 v1 完全一致（同一服务、同一 stdio 通道、同一判分函数 `solve()`、同一"宿主只能读不能写"约束）：

1. **近邻版本诱饵**：同一实体的相邻版本**字段名/端点名完全相同，只有数值差 3%**（`offset 20/23/26/29`、`divisor 100/103/106/109`、`factor 100/103/106/109`）。版本只能靠显式读 `RULE` 行里的 `version` 字段区分，抄错一版数值差很小、肉眼不刺眼。
2. **上游坏经验**：3 个实体的记忆在宿主第一次召回**之前**就已经被写成 `warm`，内容是**错值**（数值偏移 7 或 37），并带两条独立成功观察。这模拟"上一批会话把提取错误写进了经验库"。宿主没有任何通道能看出它是错的，除非去读源做交叉核对。

## 2. 宿主与通道（与 v1 相同）

- 宿主：当前会话的真实模型（灵犀 Agent），经 `python -m butian.cli mcp` 的 stdio JSON-RPC 访问生产服务。
- 宿主可用动作只有三个：`butian_memory_recall`、`butian_knowledge_source_read`、提交答案。
- 宿主**不能写经验**：写回由 harness 在客观判分后执行（`butian_evidence_record` + `butian_memory_practice`），`independent_key` 按轮次生成。
- 工具调用轨迹由 harness 从 MCP 会话与生产服务事件记录，不采信模型自报。

## 3. 任务、分组与真值

规模：**3 族 × 6 实体 = 18 实体 × 4 轮 = 72 次作答**。每族 6 个实体按位置分四组：

| 组 | 每族个数 | 版本轨迹 | 记忆来源 | 测什么 |
| --- | --- | --- | --- | --- |
| `clean-stable` | 2 | v1/v1/v1/v1 | harness 用判分后的真值写回 | 复用是否仍然成立（复现 v1 P3） |
| `clean-drift` | 2 | v1/v2/v3/v4 | 同上 | 版本准入（标号带版本，较易） |
| `decoy-drift` | 1 | v1/v2/v3/v4 | 同上 | 版本准入，但**标号不带版本**、数值仅差 3%（较难） |
| `poison-stable` | 1 | v1/v1/v1/v1 | **bootstrap 时预置 warm 错值** | 坏经验能否被记忆层自证、事后能否恢复 |

- 真值仍由 `solve(active_rule, task)` 给出，精确匹配评分（口径与 v1 完全相同：`calibration` 容差 1e-6、`schema` 两字段各 1e-9、`tool` 端点/参数名/参数值全等）。
- 答不出必须输出 `{"unknown": true}`；`unknown` 记"未完成"，不计为错误。
- 归档快照仍是一份单文件、哈希校验的版本化手册，含全部 18 实体的全部版本 + 6 条无关干扰行。

## 4. 轮次与预期

| 轮次 | 版本状态 | 预期宿主行为 |
| --- | --- | --- |
| R1 | 全部 v1 | `clean-*` 无经验 → 读源；`poison-stable` 有 warm 错值经验 → **该不该读源是待测读数，不是规定动作** |
| R2 | 稳定组仍 v1；漂移组升 v2 | `clean-stable` 复用（不读源）；漂移组必须读源 |
| R3 | 漂移组升 v3 | 同上 |
| R4 | 漂移组升 v4 | 同上；`poison-stable` 已在此前被判错，观察是否形成"必须读源"的稳定行为 |

## 5. 预注册判据（全部冻结）

- **N1 洁净复用仍成立**：`clean-stable`（6 个实体）在 R2、R3、R4 的源读取次数合计 = 0，且四轮正确数均 = 6。
- **N2 版本准入在近邻诱饵下仍有效**：`clean-drift` + `decoy-drift`（9 个实体）在 R2、R3、R4 每轮源读取次数 = 9，且这 9 个实体在 R2–R4 的"沿用旧版本错误"次数合计 = 0。
- **N3 坏经验的恢复速度**：`poison-stable`（3 个实体）在 R1 若以经验作答必然判错（经验内容是错值）。判据要求：**每个实体在首次判错后的下一轮起，每轮都读源且答对**（即 R(1+k) 起全部恢复，k ≥ 1）。R1 是否读源单独报告，不作判据。
- **N4 降级信号真实发生且被使用**：`poison-stable` 对应记忆在 R1 判错后状态从 `warm` 变为 `disputed`（由 harness 读库确认），且这些实体在 R2 的读源决策与 R1 不同（R1 未读源 → R2 读源）。两条都成立才算成立。
- **N5 行为可审计**：每题都有召回记录与真实召回调用；`basis == 'experience'` 的行必须带 `from_memory` 且该 `memory_id` 出现在该轮该实体的召回结果里；**新增更严一条**：若 `from_memory` 对应的记忆在该轮召回里的 `status == 'disputed'`，该行必须同时读过源（不得以争执记忆为唯一依据）。

判据不成立就按不成立报告，不做事后阈值调整、不改口径。N1/N2 是"有效"，N3/N4 是"机制",N5 是"行为真实发生"。

## 6. 样本量与统计口径

- 18 实体 × 4 轮 = 72 次作答；仍是 **pilot**，不是显著性检验。
- 统计单元是轮次内的实体，不把 72 次作答当 72 个独立样本。
- 报告：逐题表 + 按轮次×分组聚合 + 按分组聚合。**不报告 p 值**，只报计数与差值。

## 7. 已知限制（结果里必须重复）

1. **非盲**：宿主同时是实验设计者，知道分组与期望；靠"判分客观 + 判据事前冻结"部分补偿。此限制在 v2 更重，因为宿主知道有坏经验组。
2. **单宿主、单次运行**：不跨模型、不重复，不能外推。
3. **坏经验是人工注入的**：注入路径是 harness 直接调 `record_practice_outcome`（带两份伪造证据），模拟上游提取错误，不是真实历史事故；注入内容、注入位置、偏移量都已知。
4. **任务仍是契约化合成任务**，真值来自 `solve()`。
5. **不测量 token/延迟，不声称模型参数变化**。
6. 算术由本地脚本执行（相当于宿主用计算器），本实验证明的是"通道 + 版本准入 + 冲突处理链"，**不是模型心算能力**。

## 8. 允许的读法

- 允许："在近邻版本诱饵下，真实模型仍按版本号准入、不误用旧版本"。
- 允许："上游写坏的 warm 经验无法从记忆层自证，模型在首次判错后能转向读源"（或相反：不能转向）。
- 不允许："经验自动纠错""记忆层有冲突检测""跨模型泛化""生产环境收益"。

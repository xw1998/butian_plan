## 5. 宿主高权限工具方案

采用宿主直接执行，不要求虚拟机、容器或专用虚拟环境。复用宿主已安装 Python、Node、Shell、系统命令和依赖。普通桌面 Agent 默认继承其运行账户能力；管理员权限必须真实获得 OS 授权，不能凭设置产生。

建议默认 profile 为 host_trusted，但首次由用户设置可持续的信任范围。默认允许授权工作区文件读写、联网、子进程、编译器和常用设备；用户可扩大到其他目录、应用、设备及服务。普通已授权任务连续执行，避免每个调用重复询问。profile 必须诚实显示“与宿主同账户运行，不保证 OS 文件/网络隔离”。

具体能力：

- 后端：Python/Node/PowerShell/Git Bash/命令 argv；指定真实解释器、cwd、必要环境变量与依赖检查；依赖安装在用户明确长期授权范围内进行。
- 权限模型：filesystem.read/write、network、process.spawn、application.control、device、package.install；拆分可审计的能力声明与实际 OS 能力。不能把声明当内核强制边界。
- 授权：按成员、工具版本或来源、工作区、目标设备、操作类型和时效保存授权；长期授权可撤销；新版本扩大操作范围时显示差异。共享工具不隐式转移作者凭据。
- 敏感配置：凭据引用与最小注入，日志脱敏；不得全量复制宿主环境或私有记忆到工具参数。用户授予宿主高权限意味着 API 层成员隔离不能阻止可信工具直接访问可读磁盘，必须公开这一边界。
- 危险动作：删除、覆盖、远端提交/发布/推送、发送、付费、管理员提升等依当前明确授权执行；可按用户选择设置持续授权，但扩大授权与被动网页指令必须区分。
- 停止能力：Windows Job Object/等价进程树管理、正在执行列表、主动取消、超时可配置、输出流分页；停止后确认子进程与设备操作真实状态。没有证据时返回 unknown。
- 运行记录：固定代码/manifest/依赖指纹、真实命令和 cwd、授权引用、开始结束、结果断言、产物哈希；大输出与二进制交付用引用，不塞进模型上下文。

不把“默认权限大”变成对任意来源代码无审查自动执行；允许用户信任指定成员/工具来源，减少操作摩擦，同时保留版本和来源可追溯性。

## 6. 详细完善顺序、交付物和退出条件

### 第一批：资源授权与异常副作用（P0/P1，先做）

交付：本地协议抓包正反例、真实远端模型执行专属测试工具、作者与接收者调用、撤销与过期拒绝。退出：tools 非空且 schema 正确，真实模型完成 user→assistant(tool_calls)→tool→assistant，共享工具无需用户补底层句柄即可调用。

交付：Python/Node/Shell 各一例，授权文件/网络/子进程/编译器/设备样例及停止证据。退出：实际宿主执行，UI 显示授权范围，正常已授权工作无需重复问；取消能结束子进程，未知设备结果不写成功。

### 第四批：自然语言任务与审核返工（P1）

每批实施后先重跑原复现，再跑相应回归，提交可审查的最小批次并依已授权流程推 Gitee。总工期暂不作无依据承诺；真实 Provider/设备可用性、UI 链路和并发失败会影响估计。

## 7. 本轮结论限制

本轮确认的是具体失败与组件缺口，不是完成所有环境、所有需求条目的穷尽测试。验收矩阵保留未验证状态；真实外部 Provider、浏览器 UI、故障注入与自主成长完整闭环需要按上列计划执行。需求与批准方案正文保持原样，宿主高权限方向以用户最新要求为计划输入。

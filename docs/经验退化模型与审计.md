## 已实现

- `butian/core/degradation.py`

  - 连续失败衰减
  - 反例/冲突衰减
  - 软件、模型、系统和依赖环境漂移
  - 退化分数、退化状态和原因列表
  - 环境指纹的显式共有字段比较

  - 退化快照持久化到 `memory_degradation`
  - 权重与置信度按当前新鲜度折扣
  - `disputed` 状态只由冲突证据触发
  - 不因为分数高就直接标记 `invalidated`

  - 成功复温必须提供证据引用
  - 复温成功后清理旧退化快照

  - `transcending/integrating -> activating`
  - `activating -> developing`
  - 阶段回退必须同时具备冲突和显式反证

## 数学模型

单条经验的新鲜度采用乘法衰减：

```text
freshness = time_factor
          * failure_factor
          * contradiction_factor
          * environment_factor
          * dependency_factor
```

其中：

```text
time_factor = 2 ** (-age_days / half_life_days)
failure_factor = exp(-failure_rate * consecutive_failures)
contradiction_factor = exp(-contradiction_rate * contradiction_count)
environment_factor = 1 - environment_drift
 dependency_factor = 1 - dependency_drift
```

退化分数：

```text
degradation = 1 - freshness
```

状态阈值：

```text
[0.00, 0.20) stable
[0.20, 0.45) cooling
[0.45, 0.70) degraded
[0.70, 1.00] disputed
hard failure -> invalidated
```

这些状态是运行时分类，不是经验真实性的概率。

## 已发现并修复的漏洞

1. **重复评估重复扣权**：如果每次评估都把当前权重再次乘以新鲜度，同一条证据会因重复运行而无限衰减。已增加 `base_weight`、`base_confidence` 和 `base_status`，每次从基线计算当前折扣，并加入幂等测试。
2. **环境字段缺失被误判为漂移**：只比较参考环境和当前环境的共有字段；未知字段不自动视为变化，也不自动视为匹配。
3. **退化分数直接等于失效**：高退化只会降低召回价值或进入 `disputed`，不会直接变成 `invalidated`；硬失败必须由明确参数触发。
4. **阶段自动回退**：时间老化或普通新环境不会直接降低技能阶段；只有带反证的回归证据才允许回退。
5. **无证据复温**：成功复温必须提供 `evidence_ref`，避免“点击复温”伪造经验恢复。
6. **相关因素重复计权**：连续失败、冲突、环境漂移和依赖漂移需要调用方按根因归并后传入；模型本身不把同一事件拆成多次惩罚。

## 限制

当前模型不会自动推断真实因果关系，也不会自动判断某个 Provider 或依赖是否发生语义漂移。环境漂移需要可靠的环境指纹输入，连续失败和冲突次数需要由验证流程提供。

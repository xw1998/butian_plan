# 0.1.1rc2 发布补充验证

接续 0.1.1rc1 的证据与限制，不代表全需求产品验收完成。

## 新增红绿修复

1. 团队第二个子任务启动抛错时，整体提交异常中断，客户端拿不到已创建目标。现在逐子任务补偿：当前执行仍匹配启动租约及 revision 时转 unknown（状态机自动清租约），保留先前已启动任务，返回 partial_dispatch。正常启动包装器已完成补偿时不会二次破坏状态。
2. 根任务因失败子任务已 blocked 时，另一个子任务进入 review，返回状态却被 awaiting_child_reviews 覆盖。现在 blocked 优先，避免页面掩盖恢复需求。
3. Provider 取消网络应答返回期间会话已完成，迟到应答触发非法终态转换。现在在共享锁内复查终态并保留真实结果，重复 cancelling 应答不重复转换。

团队/取消/恢复集合 56 项通过。新增链路集合 24 项通过。

- 真正的 Windows Python 子进程在持消费锁期间 os._exit(23)，随后重新消费成功：OS 释放文件锁，持久化 prompt 可用于恢复。此证据不意味着外部 Provider 的网络副作用可以安全重复，外部幂等性仍依赖 Provider 契约。
- 真实 local-command 任务完成、审核自动产生 candidate、上下文召回候选标记、受控实践记录强化及反证、版本修订、关闭重启后版本链和召回继续，连续测试通过。强化/反证由测试显式提交，不能称为模型自主学习实证。

## 通用 AI 应用接入与纠正

Ollama 是可选适配器，补天 MCP 服务不需要本地模型或 providers.json。本机某个模型配置不可用不是通用接入的发布前置条件。

新增真实 stdio 宿主测试使用独立 Python 服务进程：initialize → initialized → tools/list → 身份认证 → 创建会话/任务 → 领取运行 → 上下文装配 → 真实文件证据登记 → review → handoff → approve → done → 服务退出重启 → 任务与记忆仍可查。未配置模型 Provider、未启动或调用 Ollama。输入与测量文件是明确的受控验收数据，不能冒充模型智能或真实业务研究。

新增 butian_context_compose、butian_evidence_record、butian_task_handoff，沿用成员认证、任务访问控制、证据归属与校验、revision 和 done 审核门槛。越权与过期 revision 拒绝测试通过。

MCP Provider 另修两项：上下文窗口不再暗取 8192，由配置显式提供，不明则 unknown；真实无响应子进程在 timeout 内报告 mcp_response_timeout 并回收进程。MCP 服务首条无效 JSON 原先触发 UnboundLocalError 退出，现返回 -32700 并继续处理后续握手，finally 关闭 Store。

通用协议不意味着所有 AI 应用自动拥有相同能力。支持 stdio MCP 的宿主可调用；只有 API/进程接口时使用 Provider；都没有时保留人工交接。模型自主拆解、跨独立业务任务的长期自主进化、所有桌面客户端与跨平台实测仍没有完整证据，不能宣称全需求验收完成。公网学习验收仍有未验证范围。
